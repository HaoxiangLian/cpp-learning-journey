## A. 概念判断

1. **错误。** `std::move` 只是产生可匹配移动入口的表达式；由随后选中的操作决定状态变化。移动 `unique_ptr` 转移管理责任，不移动被管理对象本身。
2. **错误。** 重新分配会使指向 vector 元素的迭代器、指针和引用失效；元素中的 `unique_ptr` 移动后仍管理原来的 `T`，所以仅由 `get()` 得到的 `T*` 通常仍指向同一对象。删除相应元素后才会悬空。
3. **错误。** 还要调用虚函数、对象未被按值切片，并且实际对象存在相应最终覆盖版本。普通非虚成员函数按静态类型选择。
4. **错误。** `unordered_map` 常见查找为平均常数复杂度，最坏可为线性；`map` 通常为对数复杂度。实际速度还取决于数据、哈希、比较器、缓存和实现，应测量而非绝对断言。
5. **错误。** 所有冲突访问必须使用同一同步协议，并覆盖同一共享状态；绕过锁的访问仍可能形成数据竞争，多把锁还可能死锁。

## B. 代码与状态判断

移动后 `owner` 仍存在但为空，`tasks[0]` 接手 `Add` 的独占管理责任。`observed` 指向被管理的 `Add`，而不是 vector 中的 `unique_ptr` 元素；`reserve` 可能移动智能指针元素，却没有结束 `Add`，所以此时可调用。`clear` 销毁元素，最后也销毁 `Add`，此后 `observed` 悬空，使用会产生未定义行为。

`element` 指向 vector 元素本身；若 `reserve(100)` 触发重新分配，它就失效。判断前仍应观察原容量，因为没有重新分配时规则不同。

## C. 编程练习

参考实现：[`task_queue.cpp`](task_queue.cpp)。预期输出：

```text
results: 4 7
```

`TaskQueue` 的 vector 元素独占管理任务；`push` 按值接收智能指针并移动进容器。`run_all` 通过基类接口调用虚函数，不转移任务所有权。返回的结果 vector 是独立值，不依赖队列元素的后续有效期。

## 故意错误解析

复制 vector 需要复制其中每个 `unique_ptr`，但 `unique_ptr` 的复制构造被删除，因此程序在编译期被拒绝。若要整体转移可写 `auto second = std::move(first);`；这会让 `first` 保持有效但处于合法的移后状态，不能假设所有容器实现都保留某个具体大小以外的承诺。
