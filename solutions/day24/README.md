## A. 概念判断

1. **错误。** `std::move` 只把表达式转换为可匹配移动入口的形式；后续选中的操作决定状态变化。即使 `unique_ptr` 的责任被移走，源智能指针对象仍存活、可检查和重新赋值。
2. **错误。** vector 重新分配会使指向元素本身的迭代器、指针和引用失效；移动 `unique_ptr` 元素通常不结束它管理的 `Task`。删除对应元素或销毁队列后，指向任务的观察才会悬空。
3. **错误。** `run` 必须是虚函数，引用必须绑定到仍存活且未切片的派生对象，并且派生类要有匹配覆盖版本。
4. **错误。** 动态检测只报告实际执行路径中受支持的错误；未执行路径、工具未覆盖类别和业务错误仍可能存在。
5. **错误。** 主动提取要求先不看答案输出预测、代码或口述，再依据错因修正；重读可辅助理解，但不能替代闭卷检索。

## B. 限时代码辨析

`task` 起初独占管理 `AverageTask`，`observed` 只是非拥有观察。`push` 后队列元素接手责任，`task` 为空但仍是有效智能指针对象；任务仍存活，因此队列存活且未删除该元素时，`observed->run()` 可以使用。

队列销毁会销毁智能指针元素和任务，此后 `observed` 悬空，解引用产生未定义行为，不应说成必然崩溃。`first` 是独立的结果容器，不依赖任务对象，仍可使用。

若 `run()` 抛异常，`unique_ptr` 和 vector 的 RAII 管理使沿正常对象销毁路径的任务不会泄漏。是否继续执行其他任务、是否保留已产生结果、调用方看到基本保证还是强保证，仍需由接口协议和实现提交顺序明确。

## C. 编程练习

参考实现：[`sensor_queue.cpp`](sensor_queue.cpp)。预期输出：

```text
room average: 22
motor alert: 1
processed: 2
```

实现用抽象基类定义任务接口，用 `unique_ptr` 表达队列的独占管理责任。`run_all` 返回新的结果 vector，因此结果生命周期与队列解耦。C++11 引入 `unique_ptr`，C++14 引入 `make_unique`；这里按 C++17 主线使用。

## 故意错误解析

复制 `SensorQueue` 会要求复制其 vector 元素，而 `unique_ptr` 的复制构造已删除，因此文件应在编译阶段失败。需要把责任整体交给另一对象时可以移动；仅观察队列时应传引用。不能仅为了通过编译就把独占责任改成共享责任。
