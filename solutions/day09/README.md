## 一、概念判断

1. **错**。成员在进入构造函数体前已按初始化规则建立。
2. **错**。非静态数据成员按类定义中的声明顺序初始化。
3. **对**。逆序销毁让后建立且可能依赖前面成员的子对象先结束。
4. **对**。`explicit` 不妨碍直接列表初始化。
5. **对**。完整对象的析构函数体运行后，成员子对象再按声明逆序析构。

## 二、代码分析

### A

`value_` 先使用默认成员初始化器得到 `10`，进入构造函数体后再被赋值为参数值。直接初始化写成 `A(int value) : value_{value} {}`。

### B

`doubled_` 先初始化，因为它先声明；其初始化表达式读取尚未初始化的 `raw_`，在 C++17 中属于未定义行为。仅调整列表顺序无效，必须让 `raw_` 先声明，并让列表与声明保持一致。

### C

`SensorId first{3};` 是直接初始化，合法；`SensorId second = 3;` 需要隐式转换，不能使用 `explicit` 构造函数，因此是编译错误。
