## 一、概念判断

1. **对**。变量提供名称；对象是运行时实体。今天的变量都指向普通对象，但对象的范围并不等同于“有名字的量”。
2. **错**。函数体内未提供初始化器的普通 `int` 对象没有可依赖的初值；直接读取会导致未定义行为。
3. **错**。它位于声明中，负责创建并初始化对象。只有对象已经初始化后执行的 `sample_count = 1;` 才是赋值。
4. **对**。变量不等于“可变的值”；`const` 限定约束普通修改。
5. **错**。运行时结果可以初始化 `const` 对象；初始化完成后不再通过该对象普通修改即可。

## 二、代码分析

### 题 A

精确输出：

```text
3 7
```

`second_count` 创建时用 `first_count` 当前的值完成初始化，但两者是两个不同的 `int` 对象。之后给 `second_count` 赋值不会修改 `first_count`。

### 题 B

这是**编译错误**：列表初始化拒绝从 `double` 到 `int` 的窄化。根据题目明确的“小数温度”需求，应修复为：

```cpp
double temperature{20.5};
```

不要仅为了让编译通过而丢掉小数信息。

### 题 C

直接读取函数体内未初始化的 `int` 对象会触发**未定义行为**。不能依据 C++ 标准预测输出为 0，也不能预测它一定崩溃。正确修复是：

```cpp
int sample_count{0};
```

## 三、小型编程题

完整答案见 [`sensor_snapshot.cpp`](sensor_snapshot.cpp)。核心代码是：

```cpp
const int sensor_id{12};
int sample_count{0};
double position_meter{1.25};

// 第一次输出后
sample_count = 1;
position_meter = 1.5;
```

`sensor_id` 表达本次程序运行中不应变化的身份；采样次数和位置表达会更新的状态，因此不是 `const`。

## 四、深度思考题参考

一种合理设计是：

- 设备编号：`const int`，创建时初始化，之后不赋值；
- 已采样次数：`int`，从 `0` 初始化，采样后允许赋值；
- 当前温度：`double`，用有效初值初始化，新数据到达时允许赋值；
- 告警状态：`bool`，初始化为 `false` 或由明确输入得到，状态变化时允许赋值。

这不是唯一答案。例如设备编号也可以使用更能表达业务含义的自定义类型，但那需要后续的类与枚举知识。当前关键是让类型和 `const` 选择对应真实约束。
