# Day 19 独立答案与解析

## A. 概念判断

1. **错误。** 异常离开作用域时，已经成功构造的自动对象按正常逆序销毁；尚未完成构造的对象不析构。
2. **正确。** 强保证的核心是失败像“没有发生过”；成功路径仍按接口约定修改状态。
3. **错误。** `noexcept` 是异常不得越过函数边界的承诺；若异常真的逃出，程序调用 `std::terminate`，并不要求所有 `throw` 都成为编译错误。
4. **错误。** 清理往往发生在异常传播期间；析构再抛异常可能导致 `std::terminate`。应在析构内部处理，或提供可显式调用、能报告失败的普通操作。

## B. 执行顺序

Day 19 示例中，`Session` 先创建；`calibrate` 抛出后，异常到达外层 `catch` 前先销毁 `Session`。因此 `close sensor` 必须出现在 `caught: signal lost` 之前。

## C. 编程练习

参考实现见 [`exception_safe_update.cpp`](exception_safe_update.cpp)。两个更新都遵循“先完成可能失败的检查与临时计算，最后一步才提交状态”。这使校验或解析失败时，旧值与旧容器内容保持不变。

`vector::push_back` 对本题的 `int` 元素在分配等失败时不会留下半个新元素。真实项目仍要逐项核对所调用操作的保证，不能仅凭函数名推断整个组合操作的异常安全等级。
