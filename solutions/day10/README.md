## 一、概念判断

1. **错**。`copy` 在声明时直接由 `source` 初始化，走拷贝构造语义。
2. **错**。默认成员拷贝只复制指针值，不知道数组长度和所有权契约。
3. **对**。本题独占语义要求各对象拥有独立分配，修改和析构互不影响。
4. **对**。赋值不同于初始化，必须先考虑目标当前状态与资源。
5. **错**。Rule of Three 是资源设计提醒，不是要求所有类手写特殊成员的语法强制。

## 二、代码分析

### A

`first{3}` 调用接收大小的普通构造函数；`second{first}` 用已有对象初始化新对象，调用拷贝构造；`third{1}` 先普通构造，随后 `third = first` 调用拷贝赋值。

### B

默认拷贝让 `a.data_ == b.data_`，二者指向同一动态数组。两个对象若都声称独占并在析构时 `delete[]`，第一次析构后另一个指针悬空，第二次释放产生未定义行为；不保证固定诊断或崩溃。

### C

若 `this == &other`，第一行 `delete[] data_` 同时使 `other.data_` 指向的源数组失效，后续复制成为释放后使用。即使不是自赋值，若旧数组先删除、随后分配失败，目标也已经失去原状态。应先准备新资源，成功后再替换。
