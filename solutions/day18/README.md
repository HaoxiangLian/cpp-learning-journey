# Day 18 独立答案与解析

## A. 概念判断

1. **错误。** 被移动的是管理责任；源 `unique_ptr` 对象仍存在并处于空状态，可以检查、重新赋值或销毁，但不能在为空时解引用。
2. **错误。** 如果两个对象只靠彼此的 `shared_ptr` 保持，离开外部作用域后共享拥有者数量仍不为零，对象不会自动销毁。这是循环共享造成的资源滞留。
3. **正确。** `lock()` 在被观察对象已结束时返回空 `shared_ptr`，调用者应先检查再访问。
4. **错误。** `use_count()` 是一次观察；并发环境中计数可在检查后改变，不能替代同步或正确的所有权设计。

## B. 输出预测

完成 TODO 后，输出为：

```text
moved number: 12
observed number: 20
after reset: -1
```

第一次调用把 `first` 的独占管理责任交给函数，再由返回值交给 `second`。第二部分中 `owner.reset()` 是最后一个共享拥有者离开，因此 `Job{20}` 结束；`observer` 自身仍存在，但只能得到空结果。

## C. 编程练习

参考实现见 [`smart_pointer_choices.cpp`](smart_pointer_choices.cpp)。核心不是记住函数名，而是先回答：谁负责让对象结束？若答案只有一个就优先独占；确实有多个不确定先后顺序的拥有者时才共享；只想安全查看则使用非拥有观察。

父子关系中，父节点用 `shared_ptr` 管理子节点，子节点用 `weak_ptr` 指回父节点。若反向边也使用 `shared_ptr`，父子可能在外部拥有者都离开后仍互相增加共享拥有者数量，形成循环共享。
