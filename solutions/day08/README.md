## 一、概念判断

1. **错**。类是类型；对象是该类型在程序执行中的具体实体。
2. **对**。每个类对象都有与直接非静态数据成员对应的成员子对象。
3. **错**。`private` 只限制类外直接命名；公开成员函数若不维护约束，仍能制造无效状态。
4. **对**。这是二者的默认成员访问差异；二者都能定义数据和函数成员。
5. **错**。尾置 `const` 限制通过本次调用普通修改对象，不禁止输出日志、修改外部对象等副作用，也不自动保证线程安全。

## 二、代码分析

### A

`first.value()` 为 `1`，`second.value()` 为 `0`。两个对象共享同一份类规则和成员函数实现，但各自拥有独立的 `value_` 成员子对象。

### B

取消注释后是**编译错误**：普通类外上下文不能命名 `private` 成员。访问控制不是加密或运行时隔离，调试器是否显示字段属于工具能力，不改变语言访问规则。

### C

`sensor` 是 `const` 对象，而 `id()` 没有尾置 `const`，语言不能假定这次调用不会修改对象。修复为 `int id() const { return id_; }`，不应为了调用查询函数而去掉对象的 `const`。

参考实现见 [`battery_level.cpp`](battery_level.cpp)。关键顺序是先检查候选值，再提交修改；如果校验失败，旧状态保持不变。查询函数使用尾置 `const`，让只读对象也能安全查询。
