# 第 13 天答案：虚函数、抽象类与对象表示

[返回练习](../../exercises/day13/README.md) · [返回讲义](../../days/day13.md)

## 一、概念判断题

1. **错误。** 引用只保证完整派生对象仍存在；非虚成员仍按调用表达式中写明的基类类型选择，只有满足条件的虚调用才动态选择派生实现。
2. **正确。** 真正覆盖基类虚函数的派生版本继续是虚函数。推荐写 `override`，用于让编译器检查覆盖关系。
3. **错误。** 基类函数末尾的 `const` 属于成员函数签名约束；派生版本缺少 `const`，没有覆盖该入口，写 `override` 会产生编译错误。
4. **正确。** 抽象类类型不能直接按值创建对象，但其指针或引用可以指向一个完整的具体派生对象。
5. **错误。** vtable/vptr 是常见实现，不是标准规定的名称、位置或固定大小；标准保证的是虚调用行为。

## 二、代码输出与错误分析

1. 输出依次为 `Base` 和 `2`。`view` 只是绑定到原 `Derived` 的基类子对象，没有创建新对象，也没有切片。`name()` 非虚，所以按 `Base&` 选择；`value()` 为虚函数，所以按完整 `Derived` 选择覆盖版本。
2. 基类声明是 `read() const`，派生声明缺少 `const`。`override` 要求覆盖关系成立，因此错误发生在编译阶段。删除 `override` 只会留下另一个同名函数，基类引用仍调用基类版本，并未修复设计意图。
3. `Sensor*` 只是保存将来可指向对象的地址，不创建 `Sensor` 值对象；`Sensor sensor;` 则要求直接建立仍有纯虚最终实现的抽象对象，所以程序非良构。
4. `sizeof(Record)` 给出完整对象占用的字节数，包含必要填充；`alignof(Record)` 给出完整对象的对齐要求。具体数值及填充位置属于当前实现，应运行或查询编译器，不能仅从成员列表写成跨平台常量。
