# 第 11 天答案：移动与特殊成员函数

[返回练习](../../exercises/day11/README.md) · [返回讲义](../../days/day11.md)

## 一、概念判断题

1. **错误。** `std::move` 只进行显式转换，本身不清零成员；随后选中的移动操作决定是否转移以及如何留下源状态。
2. **正确。** `T target{std::move(source)}` 初始化新对象，`target = std::move(source)` 替换已有对象状态。
3. **错误。** 被移动对象仍在生命周期内；它必须满足相应契约，可以析构，也通常可以被重新赋值。其具体可观察值不能脱离类型契约猜测。
4. **错误。** 特殊成员函数的隐式声明规则会受用户声明的析构、拷贝和移动操作影响；资源类应明确检查全部路径。
5. **正确。** Rule of Zero 不是“没有析构行为”，而是业务类不亲自手写资源管理特殊成员；`std::vector` 会在自己的析构函数中释放资源。

## 二、代码输出与错误分析

1. 深拷贝完成后通常有数组 A 和独立数组 B，源对象仍拥有 A 且内容不变；本例移动完成后仍只有原数组 A，目标接管 A，源对象仍在生命周期内但按本类契约变为空。`std::move(source)` 只把表达式显式转换为可匹配 `T&&` 的形式；随后选中的移动构造函数才读取资源句柄、把它交给新对象并按该类契约复位 `source`。
2. 两个对象会保存同一拥有型指针，最终可能对同一数组执行两次 `delete[]`。第一次释放后另一个指针悬空，第二次释放导致**未定义行为**；不能断言一定崩溃。
3. 目标原来拥有的数组不再有可用于释放它的指针，形成**内存泄漏**。正确顺序是先处理目标旧资源，再接管源资源。
4. 类把拷贝构造声明为 `= delete`，因此 `MoveOnlyBatch copy{source};` 选择已删除函数并产生**编译错误**。若要转移，应先为类实现移动构造，再写 `MoveOnlyBatch moved{std::move(source)};`。

## 三、编程题参考实现

完整实现见 [`move_only_batch.cpp`](move_only_batch.cpp)。关键状态变化是：接管前源对象持有数组 A；接管后目标持有 A，源对象记录 `count_ == 0` 且 `data_ == nullptr`。移动赋值还要先释放目标原来的数组 B。

参考输出：

```text
moved: 4 9
sources empty: true true
```

本实现显式处理 `this == &source`。这只是该自定义类型选择的契约；不要据此推断所有类型移动后都为空，或所有移动实现都必须采用同一自移动策略。
