## 一、概念判断题

1. **错误。** 数组迭代器在本例中是裸指针，但迭代器是按访问和移动能力描述的位置对象；输入迭代器只保证向前读取，不支持任意 `it + n`。
2. **正确。** `first` 是包含端，`last` 是排除端；当当前位置等于 `last` 时已经没有区间元素可读取。
3. **错误。** `std::find` 没找到时返回 `last`，结束位置不能解引用；算法不会替调用者产生默认元素。
4. **错误。** 谓词是可调用角色，普通函数、合适的函数对象或 Lambda 都可能满足；`is_even` 就能作为 `std::count_if` 的谓词。
5. **错误。** `[threshold]` 在 Lambda 创建时保存值副本；外层对象之后改变，不会自动修改已经保存的副本。
6. **错误。** `std::sort` 在 C++17 中要求 Random-access iterator，还要求元素满足交换、移动和比较等条件；写出调用形式不代表这些要求成立。

## 二、位置、算法、捕获与能力分析

1. `current` 创建后位于下标 0，可解引用得到 4；一次递增后位于下标 1，可解引用得到 9；总共三次递增后等于 `last`，只可作为结束边界比较，不能解引用。
2. `found_9` 位于下标 1，检查 `found_9 != last` 为真，可以读取 9；`found_7` 等于 `last`，检查为假，不能解引用。`std::find` 只读取本例区间，没有修改数组，也没有取得数组所有权。
3. 函数体使用外层局部对象 `threshold`，空捕获列表 `[]` 却没有允许捕获任何外层自动存储期局部对象，因此是编译错误。若判断应固定采用创建时阈值，写 `[threshold]`；若必须观察同一个外层对象之后的变化，写 `[&threshold]`，同时保证该对象活过 Lambda 的每次调用。
4. `a` 为 `true`：`by_value` 保存创建时的副本 5，所以判断 `7 >= 5`。`b` 为 `false`：`by_reference` 引用外层对象，调用时该对象已经是 8，所以判断 `7 >= 8`。
5. `std::find` 只需读取当前位置、与目标比较、向前递增并判断是否到达结束位置，因此 Input iterator 足够。`std::sort` 需要在区间内随机跳转、求位置关系并重排元素，所以要求 Random-access iterator；数组中的 `int*` 支持这些位置操作，`std::istream_iterator<int>` 不支持回退或随机跳转，也没有多遍保证。

## 三、编程题参考实现

完整实现见 [`algorithm_samples.cpp`](algorithm_samples.cpp)。它先保存同一数组的 `first`、`last`，每次查找都检查返回位置；普通函数与 Lambda 分别充当谓词；排序只在数组的随机访问迭代器区间上执行。

参考输出：

```text
found: 7
at least 5: 2
even: 2
sorted: 1 2 4 7 9
```

关键检查顺序是：

1. `std::find` 返回后先比较 `found != last`，再执行 `*found`；
2. `[threshold]` 保存值 5 的副本，判断逻辑不依赖外层对象后续是否变化；
3. `std::count_if` 负责遍历与计数，谓词只回答当前元素是否满足条件；
4. `std::sort` 修改原数组的元素顺序，但不拥有数组，`first`、`last` 在数组生命周期内仍描述同一完整范围。
