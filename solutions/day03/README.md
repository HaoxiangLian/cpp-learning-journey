## 一、概念判断

1. **错**。优先级决定语法分组，但不能单独推出所有部分的求值先后顺序；短路等顺序要依赖各运算符的具体规则。
2. **对**。两个操作数都是 `int`，所以先做整数除法得到 `2`，之后才转换为 `double` 的 `2.0`。
3. **错**。`static_cast` 明确转换意图，但浮点转整数仍可能丢失小数；超出目标整数范围还会触发未定义行为。
4. **对**。内置 `&&` 左侧为假时，整个结果已经确定，右侧不求值。
5. **错**。省略 `break` 后继续执行下一个标签是有定义的行为，但经常不符合意图；确需贯穿时可用 C++17 的 `[[fallthrough]]` 表达。

## 二、代码分析

### 题 A

精确输出：

```text
3.5
```

`7 / 2` 的两个操作数都是 `int`，先得到 `3`；随后与 `double` 值 `0.5` 相加得到 `3.5`；最后用该值初始化 `double result`。

### 题 B

精确输出：

```text
no
```

`count != 0` 为假，因此 `&&` 的右侧不求值，没有发生除法。若换成 `total / count > 2 && count != 0`，除零会在检查之前发生，整数除零触发未定义行为。

### 题 C

这是**有明确定义但结果不符合预期**。赋值把 `ready` 改为 `true`，赋值表达式的结果也为真，因此会输出 `ready`。直接检查状态即可：

```cpp
if (ready) {
    std::cout << "ready\n";
}
```

## 三、小型编程题

完整答案见 [`sensor_filter.cpp`](sensor_filter.cpp)。关键点是：

- 在转换位置使用 `static_cast<int>`，并理解这里是向零截断；
- 把就绪检查放在 `&&` 左侧；
- `continue` 只跳过索引 `2` 的本轮；
- `switch` 的各条独立路径用 `break` 结束。

## 四、深度思考题参考

一种清晰顺序是：先检查 `sensor_ready`；再用短路检查读数是否处于业务允许范围；只有这些条件都满足，才把已经确认可表示的浮点读数显式转换成整数显示值。模式是离散整数代码时可用 `switch`，而多个范围和逻辑条件更适合 `if`。转换必须位于范围检查之后，因为显式转换本身不负责保证范围。
