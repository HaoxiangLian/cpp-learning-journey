## A. 概念判断

1. **错误。** 可汇合的 `std::thread` 析构会调用 `std::terminate`，不会替程序自动等待；必须先 `join()` 或明确 `detach()`，本课优先 `join()`。
2. **错误。** 多线程并发只读且没有线程写入，不构成数据竞争；一旦存在未同步写入，就要重新检查。
3. **正确。** `std::lock_guard` 构造时取得锁，析构时释放锁，因此提前返回或异常离开作用域也不会遗漏解锁。
4. **错误。** 多把锁以不一致顺序取得，仍可能彼此等待。统一锁顺序，或用 C++17 `std::scoped_lock` 一次协调多把锁。
5. **错误。** `volatile` 不提供原子性、互斥或线程间同步；应依据操作使用 `std::atomic` 或互斥量。

## B. 执行顺序判断

`worker.join()` 返回后，工作线程已经完成，且它在结束前对 `result` 的写入对返回后的读取可见，因此保证输出：

```text
7
```

若在 `join()` 前同时读 `result`，主线程的读取可能与工作线程的写入并发，形成数据竞争；“通常谁更快”不是同步规则，不能用调度经验证明程序正确。

## C. 编程练习

参考实现：[`safe_counter.cpp`](safe_counter.cpp)。预期输出：

```text
count: 4000
```

每次循环创建一个 `std::lock_guard`，使 `++count` 的读取、计算和写回在同一时刻只由一个线程执行。两次 `join()` 还保证主线程只在两个工作线程结束后输出。

## 故意错误解析

`std::mutex` 表示一个具体的同步实体，复制它无法产生“同一把锁”的可靠语义，因此其复制构造被删除，程序非良构。需要多个使用者保护同一数据时，应让它们引用同一个互斥量，而不是复制互斥量。
