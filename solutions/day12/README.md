## 一、概念判断题

1. **正确。** `Lidar` 完整对象含一个 `Sensor` 基类子对象以及 `Lidar` 自己新增的成员；具体字节布局不是本题结论。
2. **错误。** 基类 `private` 成员仍属于基类子对象，但派生类成员函数不能直接命名访问；通常通过基类提供的 `public` 或 `protected` 操作使用。
3. **正确。** 目标的类型就是 `Sensor`，只从 `lidar` 的基类部分复制一个新 `Sensor`；派生新增状态不进入目标。这是对象切片，不是未定义行为。
4. **错误。** 引用避免按值复制和切片，但同名函数是否动态选择还要求基类接口是虚函数等条件；Day 13 再系统学习运行时多态。
5. **正确。** 常规 C++17 设计中，公开允许这种多态删除的基类应有虚析构函数；若不允许，则可用受保护的非虚析构等接口设计阻止类外通过基类指针删除。

## 二、代码输出与错误分析

1. `lidar` 包含 `Sensor` 基类部分和 `Lidar` 新增的 `beam_count_`；`sensor` 是独立的纯 `Sensor` 对象，只复制前者的基类部分，没有 `beam_count_`。
2. `const Sensor&` 参数只是让形参引用绑定到 `lidar` 内的 `Sensor` 基类子对象，没有创建新的按值参数对象，所以完整 `Lidar` 仍存在，也就没有切掉其新增状态。
3. 当基类析构非虚且实际对象类型不同，通过基类指针执行这种 `delete` 属于**未定义行为**。不能把后果缩减成“少打一行日志”或“只泄漏派生成员”；程序没有该固定保证。
4. `private` 继承使派生到基类的转换在类外不可访问，所以调用在编译期失败。若业务契约是所有调用方都可把 `Lidar` 当 `Sensor` 使用，应写 `class Lidar : public Sensor`。
