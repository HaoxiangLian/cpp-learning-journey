# 第 5 天答案与解析

## 一、概念判断

1. **错**。作用域描述名称查找；普通自动局部对象常在离开块时结束生命周期，但局部 `static` 名称离开可见区域后，对象仍可继续存在。
2. **对**。自动存储期是标准概念；机器栈是常见实现，不是标准强制的物理位置。
3. **对**。命名空间作用域对象本来就具有静态存储期，此处 `static` 的关键效果是让名称具有内部链接。
4. **错**。名称只在块内可见，但对象具有静态存储期；其动态初始化通常在第一次控制经过声明时完成，之后调用沿用同一对象。
5. **错**。静态数据成员不属于每个对象的普通成员子对象；未声明为 `thread_local` 时，类的对象共享同一静态数据成员实体。

## 二、代码分析

### A

输出为：

```text
5
1
```

第一行找到内层 `mode`，第二行在内层作用域结束后找到外层 `mode`。内层对象的修改没有倒流到外层对象。

### B

输出为 `41 42`。`id` 的名称具有块作用域；对象具有静态存储期，第一次经过声明时初始化，随后两次调用访问同一对象。

### C

失败阶段是链接。类内 `static int value;` 声明了成员及其类型，但没有提供被使用实体的定义。可以在类外写 `int Counter::value{0};`；C++17 中也可在类内写 `inline static int value{0};`。

## 三、编程题

参考实现见 [`task_id.cpp`](task_id.cpp)。关键不是背 `static` 写法，而是同时说清：名称只在函数内可见、对象存储跨调用保留、每次函数调用修改同一状态。
