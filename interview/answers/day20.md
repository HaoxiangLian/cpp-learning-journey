## Q039

**主问题**：`auto` 和 `decltype` 有什么区别？为什么 `decltype(name)` 与 `decltype((name))` 可能不同？

### 30 秒回答

`auto` 根据初始化表达式和目标声明形式推导变量类型，按值时通常去掉顶层 `const` 与引用；`decltype` 查询操作数的类型，不按通常方式求值。对未加括号的名字，`decltype(name)` 采用声明类型；`decltype((name))` 进入表达式规则，具名变量表达式是左值，因此得到 `T&`，并保留相应 `const`。两者都是编译期规则，不是动态类型。

### 完整答题逻辑

1. `auto` 出现在声明中，需要结合初始化表达式和 `auto` 周围的 `const`、`&` 等形式确定目标变量类型。
2. 按值 `auto` 通常得到独立对象并去掉顶层 `const` 与引用；`auto&`、`const auto&` 明确要求引用或只读绑定。
3. `decltype` 用于查询操作数类型，通常不执行其中表达式。
4. 未加括号的名字走声明类型规则；一般表达式再按值类别映射为 `T&`、`T&&` 或 `T`。
5. `decltype(auto)` 采用 `decltype` 规则保留引用时，必须检查被引用对象是否活得足够久。

### 连续追问与参考答案

#### 追问 1：`const int source{3}; auto value = source;` 中 `value` 能修改吗？

**参考答案**：能。这里按值推导，`source` 类型最外层的 `const` 不进入 `value` 的类型，所以 `value` 是独立的 `int` 对象。修改它不会修改 `source`；若希望保留只读引用，应写 `const auto& value = source`。

#### 追问 2：`auto&` 和 `const auto&` 在绑定与修改能力上有什么区别？

**参考答案**：`auto&` 是可按被绑定对象限定情况进行修改的左值引用，不能绑定普通临时值；`const auto&` 提供只读访问，可以绑定左值，也可以绑定临时值并按规则延长该临时对象的生命周期。两者都不复制被绑定对象，但不能让引用比对象活得更久。

#### 追问 3：`decltype(function())` 会真的调用函数吗？

**参考答案**：通常不会。`decltype` 的操作数属于不求值语境，编译器分析其类型和值类别而不执行普通函数调用；但表达式仍需满足该语境要求的语法和名称查找规则，不能因此写任意无效代码。

#### 追问 4：`decltype(auto)` 返回局部变量时有什么风险？

**参考答案**：若返回表达式按 `decltype` 规则得到引用，例如返回带括号的局部变量，函数结束后局部对象生命周期结束，调用方得到悬空引用；之后通过它访问对象是未定义行为。应按值返回，或仅返回指向调用方保证寿命对象的引用。

### 容易失分

- 把 `auto` 说成运行时动态类型。
- 说按值 `auto` 一定保留顶层 `const`。
- 忽略 `decltype` 对未加括号名字的特殊规则。
- 只报类型，不说明是否新建对象和引用寿命。

## Q040

**主问题**：什么是值类别和转发引用？`std::move` 与 `std::forward` 分别做什么？

### 30 秒回答

值类别描述表达式怎样表示对象或计算结果，左值、将亡值和纯右值会影响引用绑定与重载选择。`std::move` 无条件把实参转换成可匹配右值入口的表达式，本身不移动；转发引用是模板参数由调用推导时的 `T&&`，左值调用经引用折叠仍为左值引用，右值调用保持右值引用，`std::forward<T>` 据此有条件保留原类别。真正移动由随后选中的操作完成。

### 完整答题逻辑

1. 类型和值类别分属两个维度；值类别是表达式分类，不是对象的存储位置。
2. 左值稳定表示对象或函数，将亡值表示资源可复用的临近结束对象，纯右值用于初始化对象或计算值；后两者合称右值。
3. `std::move` 无条件进行类型转换，让右值入口可参与重载，资源是否变化看后续操作。
4. 转发引用要求形式为 `T&&` 且 `T` 在该函数调用中由实参推导。
5. 引用折叠让左值实参保持左值引用、右值实参保持右值引用；`std::forward<T>` 在函数体内恢复这个入口差别。

### 连续追问与参考答案

#### 追问 1：一个类型为 `T&&` 的具名变量表达式为什么是左值？

**参考答案**：声明类型与使用名字时表达式的值类别是两件事。名字可以被反复使用并稳定定位其所绑定对象，因此名字表达式是左值；若要再次把它作为可移动来源，需要明确使用 `std::move`，或在转发语境按原调用使用 `std::forward<T>`。

#### 追问 2：四种引用组合怎样折叠？

**参考答案**：`T& &`、`T& &&`、`T&& &` 都折叠为 `T&`，只有 `T&& &&` 折叠为 `T&&`。可记为“组合中只要出现左值引用，结果就是左值引用；两个右值引用才得到右值引用”。

#### 追问 3：任意函数参数 `T&&` 都是转发引用吗？

**参考答案**：不是。还要求 `T` 是该参数对应、并在这次调用中被推导的类型模板参数。例如普通的 `Packet&&`、类模板成员中已由类确定的 `T&&`，以及 `const T&&` 都不满足典型转发引用条件。

#### 追问 4：为什么包装函数直接传递具名形参会丢失调用者的右值性质？

**参考答案**：进入函数后，形参名字是左值表达式，所以写 `consume(value)` 只把左值交给下一层，即使调用者最初传入临时对象也一样。转发引用模板用推导结果记录入口类别，再由 `std::forward<T>(value)` 恢复它。

#### 追问 5：`std::forward` 会不会真正移动资源？

**参考答案**：不会。它按模板实参有条件地转换表达式的值类别，从而影响下一次重载选择。只有随后选中的移动构造、移动赋值或其他函数确实实现了资源转移，资源才会改变；某个右值入口也完全可以选择不移动。

### 容易失分

- 把右值定义成等号右边的表达式。
- 说 `std::move` 或 `std::forward` 自己搬运资源。
- 漏掉转发引用需要本次调用进行类型推导。
- 把完美转发说成标准保证没有任何运行时成本或业务副作用。
