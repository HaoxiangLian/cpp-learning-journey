## Q011

**主问题**：指针和引用有什么区别？函数参数应该怎样选择？

### 30 秒回答

指针是对象，保存可表示对象地址或空值等状态的指针值，可以改变为指向别处；引用在初始化时绑定实体，普通左值引用不能改绑，良定义程序中也不表示“没有对象”。参数必须有对象时可用 `T&`/`const T&`，允许缺失时可用指针并定义 `nullptr` 语义。两者都不自动延长对象生命周期，裸类型也不独立表达所有权。

### 完整答题逻辑

先比较语言属性：指针本身是对象，引用不是对象；指针可以保存空值并重新赋予另一个地址，普通引用必须建立有效绑定且不能改绑。再从接口约束选择：必有对象用引用，可选对象用指针；是否可修改由 `const` 决定。最后说明安全前提：两者都只是访问路径，调用者和被调用者必须保证被访问对象仍在生命周期内，所有权应通过更明确的资源类型表达。

### 连续追问与参考答案

#### 追问 1：引用可以为空吗？`int& ref = *pointer` 中 `pointer` 为空会怎样？

**参考答案**：良定义程序中的引用必须表示有效对象或函数，不提供类似空指针值的正常引用状态。如果 `pointer` 是空指针，初始化器 `*pointer` 已经不表示一个可绑定的对象，建立并使用这样的引用会触发未定义行为。不能以“程序没立刻崩溃”为依据宣称获得了合法空引用。

#### 追问 2：引用是否一定不占内存？

**参考答案**：标准明确不规定引用是否需要存储。编译器可以只把引用体现为别名关系，也可能在某些对象布局、调试或 ABI 场景中使用类似地址的表示。因此只能说引用不是对象、语义上绑定实体，不能承诺 `sizeof(reference)` 表示引用自身大小或它永远零开销。

#### 追问 3：给引用赋另一个对象时，引用会改绑吗？

**参考答案**：不会。`int& ref{first}; ref = second;` 中赋值表达式经由 `ref` 修改 `first`，把 `second` 的值赋给它；`ref` 仍绑定 `first`。普通引用一旦初始化不能改绑。如果业务需要可重新选择目标，应使用指针或封装明确的可选引用语义。

#### 追问 4：`const int*` 与 `int* const` 分别限制什么？

**参考答案**：`const int* p` 是 pointer to const int，`p` 自己可以改为指向别处，但不能通过 `p` 修改所指 `int`；`int* const p` 是 const pointer to int，初始化后指针值不能改变，但可通过它修改非 const 的所指对象。`const int* const` 同时限制两者。仍需单独检查对象生命周期和空值。

#### 追问 5：裸指针或引用是否表示资源所有权？

**参考答案**：C++ 裸指针或引用类型本身没有统一的“必须释放”语义；旧接口中裸指针有时确实承载所有权，所以必须阅读契约。现代 C++ 工程通常约定裸 `T*` 和 `T&` 为非拥有观察关系，用值、容器或智能指针表达所有权。这个约定是工程设计建议，不应伪装成语言禁止裸指针拥有资源。

### 容易失分

- 把引用定义成“不能为 null 的 const 指针”，忽略引用不是对象且绑定规则不同。
- 断言引用一定不占存储或一定比指针快。
- 只列语法差异，不回答可选性、`const`、生命周期和所有权。

## Q012

**主问题**：自动/动态存储期与栈/堆是什么关系？什么是悬空指针？

### 30 秒回答

先分两个问题。automatic 和 dynamic storage duration 回答对象所用存储至少持续多久；调用栈和堆回答某个编译器及运行环境通常怎样安排存储。普通局部指针可以具有自动存储期，同时指向动态对象。悬空指针是指针还存在，但所指对象已经结束；即使它非空，通过它访问原对象仍是未定义行为，不保证必然崩溃。

### 完整答题逻辑

先画出指针对象和被指对象两行，分别标记创建点与结束点。存储期回答“承载对象的存储至少保留多久”；栈、堆或寄存器回答某个编译器与运行环境通常“怎样安排位置”。然后说明两行可以不同：局部指针可以随函数结束，所指动态对象则要由相应释放操作结束。空指针表示没有目标，悬空指针表示目标曾经存在但已经结束。安全访问至少要证明非空、指向合适对象、对象仍存活且访问没有越界。

### 连续追问与参考答案

#### 追问 1：自动存储期对象是否一定在机器栈上？

**参考答案**：不一定。自动存储期先说明这类局部对象所需的存储随所属块执行而结束，它没有直接指定一个物理位置。常见桌面编译结果会把部分局部对象放在调用栈中，也可能用寄存器或省去不影响程序结果的独立存储。面试时先回答“多久”，再把“通常放哪里”作为实现补充。

#### 追问 2：一个自动存储期的指针能否指向动态存储期对象？

**参考答案**：可以。指针对象自己的存储期和所指对象的存储期是两条独立属性：函数中的 `T* p` 可以具有自动存储期，而 `p` 指向由 `new` 创建、具有动态存储期的对象。局部指针离开作用域不会自动释放该动态对象；若它是唯一访问路径并且没有正确管理，就可能泄漏。

#### 追问 3：`delete` 之后原指针会自动变成 `nullptr` 吗？

**参考答案**：不会。`delete p` 销毁相应对象并释放存储，但不会自动给变量 `p` 赋新值；`p` 随后成为不能用于访问原对象的悬空指针。代码可以紧接着写 `p = nullptr` 降低这一变量被误用的风险，但其他保存同一地址的别名不会自动同步，因此这不是所有权设计的替代品。

#### 追问 4：仅仅保存一个悬空指针值就等于已经执行了解引用吗？

**参考答案**：对象生命周期结束和执行 `*p` 是不同事件；指针成为悬空时，程序不一定已经发生一次对象访问。但标准对生命周期结束后指针值的可用方式有严格限制，尤其不能再经它访问原对象。工程上应尽快清除或封装这类状态，不依赖复制、比较或日志打印悬空值的实现表现。

#### 追问 5：为什么检查 `pointer != nullptr` 仍不能排除悬空？引用也会悬空吗？

**参考答案**：`nullptr` 检查只判断指针值是否为空，无法证明其曾指向的对象仍在生命周期内。局部对象结束、动态对象被释放或容器操作使观察位置失效后，指针可以保持非空却悬空。引用同样不会延长普通对象生命周期，若被绑定对象先结束，引用也会悬空；语法上“引用非空”不等于生命周期安全。

### 容易失分

- 把存储期直接定义成栈区或堆区，或给出固定地址增长方向。
- 把指针变量与所指对象说成同一种存储期。
- 认为非空足以证明有效，或断言悬空访问必然段错误。
