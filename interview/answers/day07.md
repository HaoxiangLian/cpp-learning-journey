## Q013

**主问题**：数组和指针是同一种类型吗？C 风格字符串与 `std::string` 怎么选？

### 30 秒回答

数组不是指针；数组对象包含固定数量的连续元素，只是在多数表达式中转换成首元素指针，函数数组形参还会调整为指针，所以长度信息常丢失。C 风格字符串是以 `\0` 终止的字符序列，接口必须依赖终止约定；`std::string` 自己管理长度和存储，现代 C++ 文本处理通常优先使用它，只有兼容 C 接口等边界才转换。

### 完整答题逻辑

先比较对象类型和内容：`int a[4]` 是含四个连续 `int` 子对象的数组，`int* p` 是保存指针值的对象。再说明数组到指针转换与函数参数调整，强调转换不携带长度。字符串部分先判断是否存在可访问的终止字符，再比较 `std::string` 的长度、存储管理和接口。最后给工程结论：业务层优先标准库类型，边界处按明确生命周期转换到 `const char*`。

### 连续追问与参考答案

#### 追问 1：`sizeof(array)` 与 `sizeof(pointer)` 为什么不同？

**参考答案**：当操作数仍具有数组类型时，`sizeof(array)` 得到整个数组对象所占字节数，包括全部元素；`sizeof(pointer)` 只得到指针对象自身大小。`sizeof` 是不会对数组操作数执行普通数组到指针转换的上下文之一。指针大小与数组元素数量没有通用关系，不能用它恢复长度。

#### 追问 2：函数参数写成 `int values[10]` 会自动检查至少有 10 个元素吗？

**参考答案**：不会。在函数参数类型形成时，这种数组形参会调整为 `int* values`，方括号中的 `10` 不成为该参数类型携带的运行时长度保证。函数若需要范围，必须另外接收长度，或使用能够表示范围的接口类型；仅在注释里写 10 也不能让编译器完成普遍检查。

#### 追问 3：数组元素连续存储是否是标准保证？越界访问会怎样？

**参考答案**：是，数组由连续分配的 N 个同类型元素子对象组成，下标从 0 到 N-1。形成尾后指针可用于范围边界比较，但不能解引用；通过内建下标访问 N 或更远位置不属于数组元素，行为未定义。标准不要求自动抛出异常、返回错误码或必然崩溃。

#### 追问 4：`char text[3]{'a', 'b', 'c'}` 是合法 C 字符串吗？

**参考答案**：不是。它是合法的三元素字符数组，但三个位置都被非零字符占用，没有 `\0` 终止标记。把它交给 `strlen`、`strcmp` 或要求终止字符串的输出接口，会在数组外继续寻找零字符并可能越界。可改为 `char text[]{"abc"};`，其数组大小为 4，或使用 `std::string`。

#### 追问 5：`std::string::size()` 是否包含 C 接口所需的终止空字符？

**参考答案**：不包含。`size()` 返回字符串管理的字符序列长度，例如 `std::string{"abc"}.size()` 为 3。需要传给只读 C 字符串接口时可在对象生命周期内使用 `c_str()`；它提供终止字符串视图，但后续可能使字符串存储变化的操作会让既有指针失效，调用方不能长期保存而忽略生命周期。

### 容易失分

- 说数组就是 const pointer，或认为指针自动保存数组长度。
- 把函数参数里的 `[10]` 当成运行时范围检查。
- 把任意字符数组叫作 C 字符串，或说越界必然抛异常。

## Q014

**主问题**：`new/delete` 与 `malloc/free` 有什么区别？为什么现代 C++ 避免裸 `new`？

### 30 秒回答

`new` 表达式按类型申请存储并初始化对象，`delete` 执行相应销毁语义并释放存储；`malloc/free` 按字节管理原始存储，不调用 C++ 构造和析构。分配族不能混用，单对象和数组形式也必须匹配。裸 `new` 把每条路径上的恰好一次释放责任交给人工，容易泄漏、重复释放或释放后使用，所以现代 C++ 优先值、字符串、容器和智能指针。

### 完整答题逻辑

从四个维度比较：`new` 创建有类型对象，`malloc` 只请求字节存储；普通 `new` 的失败机制通常是抛出 `std::bad_alloc`，`malloc` 失败返回空指针；释放必须按来源和单对象/数组形式匹配；裸指针不自动表达唯一所有者。随后区分错误：遗漏释放是泄漏，错误配对、双重释放和释放后使用属于未定义行为。工程上让资源管理对象随自身生命周期自动清理。

### 连续追问与参考答案

#### 追问 1：普通 `new` 分配失败时会返回 `nullptr` 吗？

**参考答案**：通常说的抛出形式 `new T` 在分配失败时通过异常报告，抛出能被 `std::bad_alloc` 处理器匹配的异常，不以返回 `nullptr` 表示失败。显式使用 `std::nothrow` 的形式才以空指针值表示分配失败。回答要先说明具体 `new` 形式，不能把两种契约混在一起。

#### 追问 2：为什么 `new[]` 必须配 `delete[]`，`new` 必须配 `delete`？

**参考答案**：它们创建的对象种类和删除表达式契约不同：单对象删除处理一个由相应非数组 `new` 创建的对象，数组删除处理由数组 `new` 创建的数组及其元素。标准要求删除形式与来源匹配；不匹配是未定义行为。某实现可能保存数组元素数量等额外信息，但具体布局不是可依赖的通用解释。

#### 追问 3：内存泄漏本身一定是未定义行为吗？

**参考答案**：不一定。程序可能失去一块仍已分配存储的最后管理路径而不立刻执行任何未定义操作，这就是资源泄漏；进程结束时系统通常回收进程资源也不能让设计变正确。长期运行会累积占用、导致性能下降或后续分配失败。泄漏与越界、双重释放、释放后使用应分别分类。

#### 追问 4：`delete nullptr`、重复 `delete` 和释放后使用分别怎样判断？

**参考答案**：对空指针值执行相应 `delete`/`delete[]` 是允许的，不需要手写空值分支；对同一动态对象释放两次是双重释放，行为未定义；对象释放后经原指针访问是 use-after-free，也属于未定义行为。`delete p` 不会自动把 `p` 或其他别名改成 `nullptr`。

#### 追问 5：既然学习了手动释放，工程中为什么仍优先容器和智能指针？

**参考答案**：手动配对要求所有正常返回、提前返回和异常路径都恰好释放一次，维护时很容易破坏。`std::string`、容器和智能指针把清理责任绑定到管理对象的生命周期，接口也能更明确表达长度和所有权。本课程学习裸机制是为了理解语言、旧代码和资源管理器的底层责任，不是把裸 `new/delete` 作为默认业务写法。

### 容易失分

- 只回答“`new` 是 C++、`malloc` 是 C”，没有对象创建和销毁语义。
- 声称普通 `new` 失败总返回空指针，或认为分配族可以交叉释放。
- 把泄漏、双重释放和 use-after-free 都笼统叫作段错误。
