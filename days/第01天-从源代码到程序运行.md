# 第 1 天：从源代码到程序运行

预计用时：60～90 分钟  
今日目标：独立写出、构建并运行一个最小 C++ 程序；分清源代码、可执行文件和进程。

## 1. 先把程序跑起来

打开 [hello.cpp](../examples/day-01/hello.cpp)：

```cpp
#include <iostream>

int main() {
    std::cout << "Robot ready\n";
    return 0;
}
```

Linux、macOS 或 Git Bash：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic hello.cpp -o hello
./hello
```

Windows PowerShell（MinGW g++）：

```powershell
g++ -std=c++17 -Wall -Wextra -Wpedantic hello.cpp -o hello.exe
.\hello.exe
```

正确输出：

```text
Robot ready
```

第一条命令负责构建，第二条命令才真正启动程序。不要把这两个动作合称为“运行代码”。

## 2. 关键术语索引

本表只用于定位；每个术语的唯一主定义在对应正文小节。

| 术语 | 本课用它解决什么问题 |
|---|---|
| [源代码](#源代码) | 人写下的 `.cpp` 到底是什么 |
| [构建](#构建) | `g++` 命令做了什么 |
| [可执行文件](#可执行文件) | 构建后磁盘上多出的文件是什么 |
| [进程](#进程) | 程序开始运行后出现了什么 |

### 源代码

**源代码是程序员用 C++ 语法编写、供构建工具读取的文本。**

`hello.cpp` 是源文件，里面保存的是源代码。CPU 不直接理解 `std::cout` 这样的 C++ 语句，所以 `.cpp` 文件通常不能直接作为机器程序执行。

### 构建

**构建是把一个或多个源文件转换成最终程序产物的全过程。**

本课使用：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic hello.cpp -o hello
```

其中：

- `hello.cpp` 是输入；
- `-o hello` 指定输出文件名；
- `-std=c++17` 选择 C++17；
- 三个警告选项帮助发现可疑代码。

这条命令内部会组织预处理、狭义编译、汇编和链接。今天只需要知道完整链路真实存在；第 11～12 天会逐步观察中间文件和链接错误。

### 可执行文件

**可执行文件是构建生成、能够被操作系统装载的程序文件；它本身还没有在运行。**

`hello` 或 `hello.exe` 是磁盘上的文件。你可以多次启动同一个可执行文件，每次启动都不是在创建另一份源代码。

### 进程

**进程是操作系统启动某个可执行文件后创建的一次运行实例。**

如果同时启动两次 `hello`，磁盘上仍可只有一个可执行文件，但操作系统会创建两个进程。进程结束后，可执行文件仍保留在磁盘上。

## 3. 四行关键代码分别做什么

| 代码 | 当前只需理解 |
|---|---|
| `#include <iostream>` | 让本文件能够使用标准输出设施 `std::cout`；展开过程第 11 天详讲 |
| `int main()` | 定义程序的主函数；运行时准备完成后，程序从这里进入你写的主体代码 |
| `std::cout << "Robot ready\n";` | 把文字写到标准输出；分号结束这条语句 |
| `return 0;` | 主函数返回 0，通常表示程序正常结束 |

`std::`、函数、返回值等机制会在后续课程分别展开。今天先确认每一行在当前程序中的作用，不提前背它们的完整规则。

## 4. 从文件到输出的真实顺序

```text
编写 hello.cpp
      ↓
执行 g++ 构建命令
      ↓
生成 hello 或 hello.exe
      ↓
操作系统装载该文件并创建进程
      ↓
进程输出 Robot ready，然后结束
```

必须分清三种东西：

| 对象 | 是否是磁盘文件 | 是否正在执行 |
|---|---:|---:|
| `hello.cpp` 源文件 | 是 | 否 |
| `hello` / `hello.exe` 可执行文件 | 是 | 否 |
| `hello` 进程 | 否 | 是 |

## 5. 笔试高频点

### 判断 1：构建成功等于程序逻辑正确

错误。构建成功只说明工具没有发现阻止生成程序的问题；程序仍可能算错结果、越界或陷入死循环。

### 判断 2：可执行文件就是正在运行的程序

错误。可执行文件是静态文件，进程才是一次运行实例。

### 判断 3：`g++ hello.cpp -o hello` 内部只有一个“编译”步骤

错误。日常口语常把整条命令简称为编译，但它通常由驱动程序组织多个构建阶段。

### 常见编译错误

[compile_error.cpp](../examples/day-01/compile_error.cpp) 少了一个分号。构建它并观察诊断：

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic compile_error.cpp -o compile_error
```

编译器指出的位置是排查起点，不一定永远是根因所在；本例根因就是上一条语句没有正确结束。

## 6. 面试回答

### 问题：C++ 源代码怎样变成正在运行的程序？

可以这样回答：

> 源代码先经过构建生成可执行文件。以 `g++` 为例，一条命令通常会组织预处理、狭义编译、汇编和链接。可执行文件仍只是磁盘文件；用户启动它后，操作系统装载程序、创建进程，运行时准备完成后进入 `main`。因此源代码、可执行文件和进程是三个不同概念。

常见追问：

1. 为什么构建成功仍可能运行错误？
2. 为什么同一个可执行文件可以同时运行多次？

回答时按“输入文件 → 构建产物 → 运行实例”的顺序说，不需要背一长串术语。
