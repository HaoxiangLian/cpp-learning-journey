# C++ 对象中是否包含成员函数？——区分类成员与对象内部存储

## 问题

对于下面的继承关系：

```cpp
class Sensor {
public:
    explicit Sensor(int id) : id_{id} {}
    int id() const { return id_; }

private:
    int id_;
};

class Lidar : public Sensor {
public:
    Lidar(int id, int beams)
        : Sensor{id}, beams_{beams} {}

private:
    int beams_;
};
```

一个完整的 `Lidar` 对象里有哪些逻辑部分？成员函数是否也属于对象的一部分？

---

## 结论

### 1. 从对象内部实际存储来看

一个 `Lidar` 对象可以粗略理解为：

```text
Lidar 对象
├── Sensor 基类子对象
│   └── 数据成员 id_
└── Lidar 自己的数据成员
    └── beams_
```

也就是说，具体对象主要保存的是**对象自己的状态，也就是数据成员**。

例如：

```cpp
Lidar a{1, 16};
Lidar b{2, 32};
```

可以粗略理解为：

```text
a
├── id_ = 1
└── beams_ = 16

b
├── id_ = 2
└── beams_ = 32
```

每个对象都有自己独立的一份数据。

---

### 2. 成员函数属于类，但通常不会在每个对象中各存一份

例如：

```cpp
int Sensor::id() const
```

这个成员函数当然是 `Sensor` 类的成员。

但是它的函数代码通常只有一份，不会因为创建了多个对象，就在每个对象内部再复制一份函数代码。

因此：

```text
数据成员：每个对象各有一份
成员函数：属于类定义的行为，多个对象通常共用同一份函数代码
```

所以，“成员函数属于类”与“成员函数存放在每个对象里面”是两个不同的问题。

---

## 为什么之前描述 Lidar 对象时没有写成员函数？

因为当我们说：

> 一个 `Lidar` 对象由哪些部分组成？

通常是在讨论这个对象**实际携带的数据和状态**。

因此重点写：

```text
Sensor 基类子对象 + Lidar 自己的数据成员
```

而不是把成员函数也画进对象内部。

---

## 一句话记忆

> **数据成员描述对象“有什么状态”，成员函数描述类“能做什么”。**

或者更直接地记：

> **成员函数属于类，但通常不作为每个对象内部的一份独立数据来存储。**
