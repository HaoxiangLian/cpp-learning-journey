# 第 4 天：条件、循环与作用域

预计用时：60～90 分钟  
今日目标：让程序根据传感状态选择路径、重复执行控制步骤，并正确判断变量能在哪里使用。

## 1. 先运行关节状态判断器

[joint_monitor.cpp](../examples/day-04/joint_monitor.cpp) 连续执行四个控制周期：

```cpp
for (int cycle{0}; cycle < 4; ++cycle) {
    const double error{target_angle - current_angle};
    const bool target_reached{
        sensor_ready && error <= 2.0 && error >= -2.0};

    if (!sensor_ready) {
        std::cout << "STOP\n";
    } else if (target_reached) {
        std::cout << "REACHED\n";
    } else if (error > 0.0) {
        std::cout << "MOVE_POSITIVE\n";
    } else {
        std::cout << "MOVE_NEGATIVE\n";
    }
}
```

输出：

```text
cycle 0: MOVE_POSITIVE
cycle 1: MOVE_POSITIVE
cycle 2: REACHED
cycle 3: REACHED
```

## 2. 关键术语索引

| 术语 | 本课用它解决什么问题 |
|---|---|
| [条件](#条件) | 程序依据什么选择路径 |
| [分支](#分支) | `if/else` 怎样只执行一条路径 |
| [循环](#循环) | 怎样重复执行控制步骤 |
| [作用域](#作用域) | 一个名字能在哪些代码中被找到 |
| [短路求值](#短路求值) | `&&` 和 `||` 何时跳过右侧表达式 |

### 条件

**条件是用于决定控制流方向、求值后可判断为真或假的表达式。**

比较运算 `error > 0.0` 产生 `bool` 结果。`true` 表示条件成立，`false` 表示不成立。`!sensor_ready` 对布尔值取反。

### 分支

**分支根据条件，只执行若干备选语句中的相应路径。**

一组 `if / else if / else` 从上到下检查。遇到第一个成立的条件后执行对应代码块，并跳过同组后续分支。因此更紧急的 `!sensor_ready` 应放在运动判断之前。

### 循环

**循环是在条件保持成立时重复执行一段代码的控制结构。**

```cpp
for (int cycle{0}; cycle < 4; ++cycle)
```

它依次完成初始化 `cycle{0}`、检查 `cycle < 4`、执行循环体、执行 `++cycle`。本例循环体运行四次，`cycle` 依次为 `0、1、2、3`。

### 作用域

**作用域是一个名字能够被名称查找找到的程序区域。**

`cycle` 和循环体内的 `error` 只在相应 `for` 结构中可用。离开右花括号后再写 `error`，编译器找不到这个名字。[scope_error.cpp](../examples/day-04/scope_error.cpp) 会因此编译失败。

作用域讨论名字在哪里可见，不等同于对象究竟存在多久；对象生命周期会在第 10 天单独讲解。

### 短路求值

**短路求值是 `&&` 或 `||` 根据左侧结果决定不再求值右侧表达式。**

对 `A && B`，若 `A` 为假，整体必为假，`B` 不执行；对 `A || B`，若 `A` 为真，整体必为真，`B` 不执行。它常用于先检查对象是否可用，再访问相关数据。

## 3. 追踪四次循环

| `cycle` | `current_angle` | `error` | 选中的分支 |
|---:|---:|---:|---|
| 0 | 84 | 6 | `MOVE_POSITIVE` |
| 1 | 86 | 4 | `MOVE_POSITIVE` |
| 2 | 88 | 2 | `REACHED` |
| 3 | 90 | 0 | `REACHED` |

循环体末尾把当前角度加 `2.0`。这个修改影响下一次迭代，不会回头改变本次已经计算出的 `error`。

## 4. 笔试高频点

### 边界错误

如果把 `cycle < 4` 写成 `cycle <= 4`，循环会运行五次，因为 `0、1、2、3、4` 都满足条件。数组和容器题中，这类多执行一次的错误经常导致越界。

### 悬空 else

没有花括号时，`else` 与最近的尚未匹配的 `if` 配对。工程代码建议保留花括号，避免缩进看起来正确、实际控制关系错误。

### 在条件中误写赋值

`if (state = 1)` 修改 `state`，然后判断赋值结果；`if (state == 1)` 才是比较。启用警告通常能帮助发现前一种可疑写法。

## 5. 面试回答

### 问题：`&&` 的短路求值有什么工程作用？

> `A && B` 会先求值 `A`。如果 `A` 为假，整个表达式已经确定为假，`B` 不再执行。工程中常把安全性检查放左侧，例如先确认指针非空，再访问指针指向的对象；这样既表达前置条件，也避免无效访问。
