## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>
#include <utility>

class Device {
public:
    virtual ~Device() = default;
    virtual std::string name() const = 0;
    virtual void update() = 0;
};

class Motor final : public Device {
public:
    explicit Motor(std::string name) : name_{std::move(name)} {}
    std::string name() const override { return name_; }
    void update() override { ++cycles_; }
private:
    std::string name_;
    int cycles_{};
};

class DeviceManager {
public:
    void add(std::unique_ptr<Device> device) {
        devices_.push_back(std::move(device));
    }
    void update_all() {
        for (auto& device : devices_) device->update();
    }
private:
    std::vector<std::unique_ptr<Device>> devices_;
};

int main() {
    DeviceManager manager;
    manager.add(std::make_unique<Motor>("joint-1"));
    manager.update_all();
    std::cout << "updated\n";
}
```

## 第二遍：从示例推到可迁移规则

### 1. 先画所有权，再写类

管理器是设备的唯一所有者，因此容器使用 `unique_ptr<Device>`。外部临时访问可以返回引用或非拥有指针；没有共同存活责任就不使用 `shared_ptr`。

### 2. 接口只放共同稳定操作

若只有电机需要 `set_torque`，不要硬塞进所有设备的基类。基类只保留确实共同的 `name`、`update` 等操作，具体能力可通过更窄接口或具体服务表达。

### 3. 按值接收 `unique_ptr` 表达转移

`add(unique_ptr<Device>)` 明确调用者要交出所有权。函数内部 `std::move` 进入容器后，形参变空；这比裸指针参数更能表达释放责任。

### 4. 错误路径与 RAII

若 `push_back` 或设备构造抛异常，已经建立的智能指针和容器成员会自动清理。系统不需要在每个返回点手写 `delete`。

### 5. 项目验收

至少增加第二种设备、拒绝空所有者、为更新次数写测试，并在 ASan/UBSan 下运行。面试时说明一个接口取舍和一个所有权取舍。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
void add(Device* device) {
    devices_.push_back(std::unique_ptr<Device>{device});
}

// 调用者不清楚 add 是否接管，之后又 delete device
```

### 根因

裸指针接口没有表达所有权转移，容易形成重复释放或泄漏。改为按值接收 `unique_ptr<Device>`，让类型和移动语法明确责任。

> 我先画出设备所有权：管理器独占设备，因此使用 `vector<unique_ptr<Device>>`。具体设备继承稳定的 `Device` 接口，通过虚函数更新；基类有虚析构。`add` 按值接收 `unique_ptr`，调用点必须显式移动，所有权转移清楚。容器和智能指针提供 RAII，异常或提前返回也不会泄漏。

###### 术语-D26-01

**接口类**

- 新手先这样理解：只向调用者暴露共同操作的抽象基类。
- 更准确地说：接口类通常包含虚析构和纯虚成员函数，尽量不承担可变共享状态。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

**依赖倒置**

- 更准确地说：这是设计原则而非 C++ 关键字；运行时多态是其一种实现手段。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D26-04

**独占所有权容器**

- 新手先这样理解：容器中的每个智能指针独占一个设备对象。
- 更准确地说：`vector<unique_ptr<Device>>` 可移动、不可复制元素，容器销毁会沿虚析构路径销毁设备。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D26-05

**工厂函数**

- 新手先这样理解：创建具体对象并以接口所有者返回。
- 更准确地说：工厂封装具体类型选择和构造失败处理，常返回 `unique_ptr<Base>`。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D26-06

**系统不变量**

- 新手先这样理解：对象公开操作前后都必须保持的整体约束。
- 更准确地说：例如管理器不保存空设备、设备名称非空；应在构造和修改接口中维护。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。
