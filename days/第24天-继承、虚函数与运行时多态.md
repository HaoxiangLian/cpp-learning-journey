## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class Sensor {
public:
    virtual ~Sensor() = default;
    virtual std::string name() const = 0;
    virtual double read() const = 0;
};

class ForceSensor final : public Sensor {
public:
    explicit ForceSensor(double value) : value_{value} {}
    std::string name() const override { return "force"; }
    double read() const override { return value_; }
private:
    double value_{};
};

int main() {
    std::vector<std::unique_ptr<Sensor>> sensors;
    sensors.push_back(std::make_unique<ForceSensor>(3.2));
    for (const auto& sensor : sensors) {
        std::cout << sensor->name() << ": " << sensor->read() << '\n';
    }
}
```

## 第二遍：从示例推到可迁移规则

### 1. 继承先表达可替换接口，不表达所有关系

只有当调用者能够把派生对象当作基类接口使用时，公有继承才合适。机器人包含传感器通常是“拥有”关系，应使用成员或智能指针；力传感器“是一种”传感器才适合接口继承。

### 2. `virtual`、`override` 和纯虚函数分别做什么

基类用 `virtual` 建立动态分派入口；`= 0` 令函数成为纯虚函数并使类保持抽象；派生类写 `override` 让编译器检查签名确实覆盖。若参数或 `const` 写错，`override` 会在编译期暴露问题。

### 3. 静态类型与动态类型

变量 `sensor` 的表达式静态类型是 `unique_ptr<Sensor>`，但它拥有的对象动态类型是 `ForceSensor`。非虚接口主要由静态类型决定；虚调用在运行时使用动态类型选择最终覆盖。

### 4. 为什么析构必须进入接口设计

所有者类型是 `unique_ptr<Sensor>`，销毁动作最终相当于经基类指针删除。虚析构使销毁先进入派生类，再完成基类部分；它不是“为了能继承”而机械添加，而是由删除路径决定。

### 5. 避免切片

函数若写成 `void print(Sensor sensor)`，派生对象按值传入时只留下基类部分，而且抽象基类甚至不能这样传。多态参数使用 `const Sensor&`、`Sensor&` 或明确所有权的智能指针。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
class Base {
public:
    ~Base() = default; // 非虚
};

class Derived : public Base {
public:
    ~Derived() { /* 释放派生资源 */ }
};

Base* value = new Derived;
delete value; // 未定义行为
```

### 根因

基类指针承担删除路径，却没有虚析构。修复为 `virtual ~Base() = default;`，或彻底禁止通过基类指针拥有和删除对象。

> 运行时多态让调用者依赖基类接口，而由对象动态类型选择覆盖实现。基类声明虚函数，派生类用 `override` 提供实现；通过基类引用或指针调用才保留多态。若对象会经基类所有者销毁，基类析构必须为虚。按值传递基类会发生对象切片，因此多态接口通常使用引用、指针或智能指针。

###### 术语-D24-01

**基类**

- 新手先这样理解：提供公共接口和可复用基类部分的类。
- 更准确地说：基类是在继承关系中被派生类扩展的类；它可声明虚函数，使通过基类引用或指针的调用按动态类型分派。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D24-02

**派生类**

- 新手先这样理解：在基类接口之上提供具体实现的类。
- 更准确地说：派生类包含基类子对象，并可覆盖可访问的虚函数；继承不自动表示现实世界的“拥有”关系。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D24-03

**虚函数**

- 新手先这样理解：通过基类接口调用时，可由实际对象类型选择实现。
- 更准确地说：虚函数参与动态分派；派生类用相同签名覆盖时，基类指针或引用调用会选择最终覆盖函数。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D24-04

**动态绑定**

- 新手先这样理解：运行时根据对象的动态类型决定调用哪个覆盖函数。
- 更准确地说：动态绑定发生在满足虚调用条件的表达式上；普通非虚调用在编译期确定。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D24-05

**抽象类**

- 新手先这样理解：含纯虚函数、不能直接创建对象的接口类。
- 更准确地说：含至少一个最终覆盖仍为纯虚函数的类是抽象类，不能实例化，但可作为指针或引用接口。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D24-06

**虚析构**

- 新手先这样理解：保证通过基类所有者销毁完整派生对象。
- 更准确地说：若对象可能经基类指针删除，基类析构函数应为虚；否则删除派生对象会产生未定义行为。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

###### 术语-D24-07

**对象切片**

- 新手先这样理解：按值复制到基类对象时，派生类特有部分被丢弃。
- 更准确地说：用派生对象初始化基类值对象只复制基类子对象；多态接口通常通过引用或指针传递。
- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。
