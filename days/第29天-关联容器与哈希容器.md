## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <iostream>
#include <map>
#include <string>
#include <unordered_map>

int main() {
    std::map<std::string, double> force_limits{
        {"arm", 12.5},
        {"gripper", 6.0},
        {"wrist", 4.5},
    };

    const auto wrist = force_limits.find("wrist");
    if (wrist != force_limits.end()) {
        std::cout << "wrist limit = " << wrist->second << "\n";
    }

    std::unordered_map<std::string, int> error_counts;
    auto [it, inserted] = error_counts.try_emplace("arm", 0);
    ++it->second;

    std::cout << "arm errors = " << error_counts.at("arm") << "\n";
    std::cout << "ordered first key = " << force_limits.begin()->first << "\n";
}
```

## 程序一步步发生了什么

| 时刻或语句 | 具体状态 | 这一步说明什么 |
|---|---|---|
| `force_limits` 构造后 | 3 个“设备名 → 阈值”条目 | `map` 按键排序 |
| `find("wrist")` | 返回指向现有条目的迭代器 | 未复制整张表 |

## 第二遍：从示例推到可迁移规则

### 1. 从线性扫描到按键查找

当问题是“找名为 wrist 的设备”时，键就是设备名，值就是状态或阈值。关联容器让数据结构与问题一致。`vector` 仍适合按顺序遍历；不是有了 map 就淘汰 vector。

### 2. map 与 unordered_map 怎么选

`map` 的遍历顺序稳定为按键排序，查找和插入通常是 O(log n)。`unordered_map` 不保证遍历顺序，平均查找通常是 O(1)，但依赖哈希质量并可能重新散列。面试中不要只背复杂度，还要说是否需要顺序、键是否可哈希、数据量与内存开销。

### 3. find、at、operator[] 的行为不同

`find` 只查找；`at` 要求键已存在，否则抛出异常；非 const 的 `operator[]` 在键不存在时会先创建默认值。这三者不是写法偏好，而是不同语义。读数据时若不想改容器，优先 `find` 或 `at`。

### 4. 迭代器和失效规则

`map` 插入通常不会让已有迭代器失效，删除只让指向被删元素的迭代器失效。`unordered_map` 重新散列时迭代器可能全部失效。保存迭代器跨越插入操作前，必须确认容器规则。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, double> limits{{"arm", 12.5}};
    if (limits["camera"] == 0.0) {
        std::cout << "camera not configured\n";
    }
    std::cout << "size = " << limits.size() << "\n";
}
```

### 根因

`limits["camera"]` 不是纯查询：键缺失时会插入 `camera -> 0.0`，所以输出 `size = 2`。若意图只是判断是否存在，应使用 `find` 或 C++20 的 `contains`；本课程按 C++17 使用 `find`。
