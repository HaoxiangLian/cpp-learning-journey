## 📖 核心知识重构

今天讨论“间接访问”：不复制一个新值，而是通过地址或绑定关系访问既有对象。指针和引用都不会延长普通局部对象的生命周期，也不会仅凭类型自动说明谁负责释放资源。

### 机制一：先判断对象何时还能用，再讨论它通常放在哪里

**实际问题**：面试中常问“局部变量在栈上，`new` 出来的对象在堆上吗？”如果直接回答“是”，初学者很容易进一步误以为“指针一定在堆上”或“出了函数，所有相关对象都会一起消失”。真正需要先判断的是每个对象何时创建、何时结束。

**概念落点**：先把问题拆成两层：

1. **时间问题**：这个对象的存储至少保留到什么时候？C++ 用 automatic、static、dynamic 等存储期回答。
2. **位置与做法问题**：编译器和运行环境具体怎样安排这些存储？常见答案才会涉及调用栈、寄存器或堆。

现在再给正式表述：[调用栈与堆（call stack and heap）](../docs/glossary/day06.md#调用栈与堆call-stack-and-heap)是常见程序运行环境组织存储的两种方式：调用栈通常随函数调用和返回保存、移除本次调用所需的信息，堆通常为程序运行期间提出的内存申请提供空间；C++17 不规定它们必须采用某种固定布局。

==初学者先记：普通局部对象通常随所属块结束；`new` 创建的动态对象由相应释放操作结束。栈与堆是常见放置方式，不是这两个时间规则的定义。==

**代码与机制**：

```cpp
void process() {
    int local{7};
    int* dynamic_value{new int{9}};

    local = 8;
    *dynamic_value = 10;

    delete dynamic_value;
}  // local 和 dynamic_value 在这里结束
```

`new/delete` 的完整规则在第 7 天学习；这里先只跟踪三个不同对象：

| 对象 | 何时创建、何时结束 | 常见实现可能怎样放置 |
|---|---|---|
| `local` 表示的 `int` 对象 | 执行声明时创建；离开函数块时结束 | 常放在调用栈中，也可能由编译器用寄存器等方式处理 |
| 指针对象 `dynamic_value` | 执行声明时创建；离开函数块时结束 | 它本身也是普通局部对象，常放在调用栈中 |
| `new int{9}` 创建的 `int` 对象 | 执行 `new` 时创建；对应 `delete` 时结束 | 默认分配机制通常从堆或自由存储相关区域提供空间 |

注意第二、三行：**指针对象本身**和**指针指向的对象**不是同一个对象，也完全可以具有不同存储期。`delete dynamic_value;` 结束的是第三行的动态 `int`；它不会让局部指针变量立刻消失，也不会自动把该变量改成 `nullptr`。

现在就能解释两个抽象说法：

- “语言规则”或“标准语义”指 C++ 代码必须具有的含义，例如 `local` 离开块后不能继续当作原对象使用，动态 `int` 要按动态对象规则管理。
- “实现方式”或“实现模型”指编译器和运行环境怎样完成这些要求，例如某次编译把局部值放在调用栈还是寄存器中。

第一遍做题只依据“何时创建、何时结束”判断安全；只有分析性能、汇编或调试器显示时，才继续追问具体放在哪里。`new` 默认通常使用堆相关机制，但分配函数可以替换，所以不要背“堆一定怎样增长”或“只要在栈上就一定更快”这类绝对结论。

**错误做法与修复**：

> 错误结论：只要变量写在函数里，它一定在栈上；只要是指针，它一定指向堆。

分类：**概念判断错误**。指针对象本身可以具有自动存储期，它也可以指向另一个自动对象、静态对象、动态对象或不指向任何对象。修复时画两行：第一行写“指针对象何时结束”，第二行写“被指对象何时结束”，不要用“它在栈上/堆上”把两者混成一个对象。

**小检查**：`int value; int* p{&value};` 中，`p` 是不是“堆变量”？它当前指向的对象是否具有动态存储期？
	不是，没有；
### 机制二：指针保存可重新选择的间接访问值，解引用前必须证明它指向有效对象

**实际问题**：某个传感器结果可能存在，也可能缺失；函数需要表达“有目标就写入，没有目标就返回失败”。值传递表达不了原地修改，可选对象也不能靠一个必定绑定的引用完整表达。

先只看这四行发生了什么：

```cpp
int speed{10};
int* selected{&speed};
*selected = 15;     // speed 变为 15
selected = nullptr; // selected 现在不指向对象
```

普通话结论是：`selected` 和 `speed` 是两个对象。`selected` 可以保存“怎样找到 `speed`”的信息，所以 `*selected` 能修改 `speed`；它也可以在之后改成“不指向任何对象”。

**概念落点**：

- [指针（pointer）](../docs/glossary/day06.md#指针pointer)是具有指针类型的对象；对象指针的值可以表示某个对象的地址、数组尾后位置、空指针值或无效指针值，只有满足相应有效性条件时才能通过它间接访问对象。
- [空指针与 `nullptr`（null pointer and nullptr）](../docs/glossary/day06.md#空指针与-nullptrnull-pointer-and-nullptr)：空指针值是不指向任何对象或函数的指针值，`nullptr` 是 C++11 引入、可转换为相应空指针值的专用字面量。

==`&object` 取得对象地址，`*pointer` 执行间接访问。==指针可以在之后改为指向别的对象；也可以显式保存空指针值，因此“可能没有对象”是常见指针接口语义。

**代码与机制**：把上面的访问方式放进一个允许“没有目标”的函数接口：

```cpp
bool assign_if_present(int* target, int value) {
    if (target == nullptr) {
        return false;
    }
    *target = value;
    return true;
}

int speed{10};
int* selected{&speed};
assign_if_present(selected, 15);  // speed 变为 15
selected = nullptr;               // 现在不指向对象
```

`target` 是按值传递的指针形参：函数得到的是指针值的副本，但两个指针值都可以指向同一个 `speed`，所以 `*target` 修改的是 `speed`。修改 `target` 自己只会改变形参指针，不会让调用方的指针重新指向；若要修改调用方指针，要使用返回值或“引用到指针”等后续组合。

`const` 与 `*` 的位置要从被约束的对象读：

```cpp
const int* view{&speed};  // pointer to const int：可改指向，不能通过 view 改 speed
int* const fixed{&speed}; // const pointer to int：不能改指向，可通过 fixed 改 speed
```

原始指针类型本身不自动表达所有权。现代工程通常把裸指针当作非拥有观察者；真正的资源所有权在第 18 天用智能指针系统表达。

**错误做法与修复**：

```cpp
int* selected{nullptr};
std::cout << *selected << '\n';  // 解引用空指针
```

分类：**未定义行为**。它不保证产生段错误，也不保证某个输出。修复是仅在接口允许空值时先检查，或在业务保证必须有对象时改用引用并在调用处建立有效绑定。

**小检查**：`target` 按值传递为什么仍能修改 `speed`？函数修改的是指针对象、指针值，还是指针所指对象？

> 你的记录：利用指针，直接通过地址解引用修改了 `speed`；修改的是指针所指对象。

这条判断正确。再说完整一步：`target` 虽然是独立的指针对象，但它保存的指针值仍指向 `speed`，所以 `*target = value` 修改的是 `speed`，不是 `target` 本身。


> [!NOTE] 解引用
> 当指针确实指向一个仍然存在、类型合适的对象时，表达式 `*pointer` 表示那个对象；读取 `*pointer` 就是读取该对象，给 `*pointer` 赋值就是修改该对象。是否允许修改还要看 `const`，是否安全还要检查非空、生命周期和边界。先按“通过指针找到对象”理解，不需要先想象某种固定物理内存布局。

### 机制三：引用在初始化时绑定对象，适合表达“必须存在且不转绑”的别名关系

**实际问题**：一个函数必须原地限制速度，并且“没有速度对象”不属于合法输入。如果每次都接收指针并检查 `nullptr`，接口反而隐藏了这个前置条件。

先观察别名的效果：

```cpp
int speed{10};
int& alias{speed};
alias = 11;  // speed 也变为 11
```

这里不是两个独立的 `int` 对象。`alias` 是访问 `speed` 的另一个名字；给 `alias` 赋值，就是给已经绑定的 `speed` 赋值。

**概念落点**：[引用（reference）](../docs/glossary/day06.md#引用reference)是初始化时绑定到对象或函数、随后以该被绑定实体的别名参与表达式的语言实体；良定义程序中的引用必须表示有效实体，普通左值引用不能在绑定后改绑到另一个对象。

引用不是对象；标准甚至不规定引用是否必须占用存储。把它直观理解为“另一个名字”很有帮助，但正式规则仍是绑定与引用初始化，不能据此推断机器代码必定没有地址或开销。

**代码与机制**：

```cpp
void increase(int& value) {
    ++value;
}

int speed{10};
increase(speed);  // speed 变为 11
```

调用 `increase(alias)` 时，函数形参 `value` 绑定到 `speed`。因此函数中执行 `++value`，改变的就是 `speed`；这里没有再创建一个独立的 `int` 形参对象。

初学者在源代码层面记住“`value` 是 `speed` 的别名”就够了。不要进一步背成“引用一定不占内存”或“必定共用一个物理地址”：C++ 规定的是绑定和访问效果，编译器具体如何表示引用属于实现方式。


`int&` 是左值引用类型（lvalue reference）。声明引用时通常必须给出初始化器；`alias = 20;` 不是让引用改绑，而是经由别名给 `speed` 赋值。若函数只读不改，常用 `const T&`；对 `int` 这类小标量，按值传递通常更简单，引用并非一律更快。

选择接口时先表达语义：

- 对象必须存在，函数不接管所有权：优先考虑 `T&` 或 `const T&`。
- 对象允许缺失：可以使用 `T*`/`const T*` 并定义 `nullptr` 的含义。
- 需要转移或共享所有权：裸指针和引用都不足以独立表达，留到智能指针章节。

**错误做法与修复**：

```cpp
int& alias;  // 故意错误：普通引用声明缺少初始化器
```

分类：**编译错误**。引用不是稍后再决定目标的空槽。修复为在声明时绑定有效对象：`int value{0}; int& alias{value};`。若业务确实允许暂时没有目标，使用初始化为 `nullptr` 的指针并在使用前检查。

**小检查**：执行 `int a{1}; int b{2}; int& r{a}; r = b;` 后，`r` 是否改为绑定 `b`？`a`、`b` 各是多少？
	不是；a=2; b=2;
### 机制四：指针或引用不会延长普通对象生命周期，非空也可能悬空

**实际问题**：指针已经检查过不是 `nullptr`，为什么仍可能出错？因为“地址数值非空”只排除一种情况，不能证明所指对象仍在生命周期内。

先按执行顺序观察两个对象：

```cpp
int* selected{nullptr};
{
    int local{42};
    selected = &local;
}  // local 生命周期结束；selected 非空但已经悬空

// std::cout << *selected;  // 若执行：未定义行为
```

普通话结论是：右花括号只结束了 `local`；外面的 `selected` 仍存在，但它原来指向的对象已经没有了。非空只说明它没有保存空指针值，不能把已经结束的对象“救回来”。

**概念落点**：[悬空指针或引用（dangling pointer or reference）](../docs/glossary/day06.md#悬空指针或引用dangling-pointer-or-reference)是仍存在但所指或所绑定对象的==生命周期已经结束==，因而不能再用于正常访问该对象的指针或引用。

**代码与机制**：离开块后，`selected` 指针对象本身仍存在，它保存的比特也可能看起来没有变化；变化的是被指对象 `local` 的生命周期已经结束。对象结束后，对原地址的使用受到严格限制，不能把“内存里似乎还有 42”当作继续访问对象的许可。

同理，返回局部对象的指针或引用会把即将失效的访问路径交给调用方：

```cpp
const int* bad() {
    int local{7};
    return &local;  // 返回后悬空
}
```

**错误做法与修复**：分类为**悬空指针**；随后通过返回值间接访问对象是**未定义行为**。不要说“必然输出垃圾值”或“必然崩溃”。对于小对象，优先按值返回；若必须返回观察关系，被观察对象必须由调用方或更长寿命的所有者管理，并把生命周期约束写进接口。

把悬空指针赋为 `nullptr` 可以帮助后续检测，但只有仍持有该指针的代码能这样做；其他别名不会自动同步变空，因此根本方案是让所有权和生命周期清晰。

**小检查**：为什么 `pointer != nullptr` 不能证明 `*pointer` 安全？还需要证明哪两个条件？

> 你的记录：需要继续检查指针是否正确初始化，以及所指对象的生命周期是否已经结束。

方向正确。把条件补全为：它必须指向本次允许访问的对象、该对象仍在生命周期内，而且访问没有越过对象或数组边界。`pointer != nullptr` 只排除了“空指针”这一种状态。
## 💻 最小可运行示例

完整代码位于 [`examples/day06/main.cpp`](../examples/day06/main.cpp)。

```cpp
#include <iostream>

bool assign_if_present(int* target, int value) {
    if (target == nullptr) {
        return false;
    }
    *target = value;
    return true;
}

void increase(int& value) {
    ++value;
}

int main() {
    int speed{10};
    int* speed_pointer{&speed};
    int& speed_reference{speed};

    *speed_pointer = 12;
    increase(speed_reference);
    assign_if_present(&speed, 17);

    const int limit{20};
    const int* limit_view{&limit};
    int* optional_target{nullptr};

    std::cout << "speed: " << speed << '\n';
    std::cout << "through pointer: " << *speed_pointer << '\n';
    std::cout << "through reference: " << speed_reference << '\n';
    std::cout << "limit: " << *limit_view << '\n';
    std::cout << std::boolalpha
              << "empty update: " << assign_if_present(optional_target, 5) << '\n';
}
```

预期输出：

```text
speed: 17
through pointer: 17
through reference: 17
limit: 20
empty update: false
```

观察重点：指针形参按值传递仍可间接修改同一对象；引用表达必有对象；`nullptr` 分支在解引用前终止；所有访问都发生在 `speed` 和 `limit` 的生命周期内。

## 🐛 错误代码诊断

### 反例 A：引用没有初始化器

[`exercises/day06/broken/uninitialized_reference.cpp`](../exercises/day06/broken/uninitialized_reference.cpp) 被显著标记为故意错误，不进入正常构建目标。

分类：**编译错误**。普通引用声明必须建立绑定，不能创建一个等待以后指向对象的“空引用”。

### 反例 B：空指针解引用

`int* p{nullptr}; int value{*p};` 一旦求值 `*p`，行为未定义。检查空值必须发生在解引用之前。

### 反例 C：非空悬空指针

指针保存局部对象地址后，局部对象先结束生命周期。指针值可能仍非空，但经它访问对象属于未定义行为；`nullptr` 检查无法发现这种生命周期错误。

## 🎤 高频面试实战

本节保留当日主问题的答题框架。先独立口述，再到[第 6 天面试答案](../interview/answers/day06.md)逐题核对所有连续追问。

### 题 1：指针和引用有什么区别？函数参数应该怎样选择？

**30 秒口头回答**：指针是对象，保存可表示对象地址或空值等状态的指针值，可以改变为指向别处；引用在初始化时绑定实体，普通左值引用不能改绑，良定义程序中也不表示“没有对象”。参数必须有对象时可用 `T&`/`const T&`，允许缺失时可用指针并定义 `nullptr` 语义。两者都不自动延长对象生命周期，裸类型也不独立表达所有权。

**完整答题逻辑**：先比较“是否是对象、能否为空、能否改指向/改绑、使用语法”；再根据接口的可选性和可修改性选择；最后补上生命周期与所有权边界，避免只背语法表格。

**可能连续追问**：

- 引用可以为空吗？`int& ref = *pointer` 中 `pointer` 为空会怎样？
- 引用是否一定不占内存？
- 给引用赋另一个对象时，引用会改绑吗？
- `const int*` 与 `int* const` 分别限制什么？
- 裸指针或引用是否表示资源所有权？

**容易失分的说法**：说引用只是“不能为 null 的 const 指针”；说引用一定零开销且不占存储；把指针形参按值传递误解为不能修改所指对象；忽略悬空和所有权。

### 题 2：自动/动态存储期与栈/堆是什么关系？什么是悬空指针？

**30 秒口头回答**：先分两个问题。automatic 和 dynamic storage duration 回答对象所用存储至少持续多久；调用栈和堆回答某个编译器及运行环境通常怎样安排存储。普通局部指针可以具有自动存储期，同时指向动态对象。悬空指针是指针还存在，但所指对象已经结束；即使它非空，通过它访问原对象仍是未定义行为，不保证必然崩溃。

**完整答题逻辑**：先画出指针对象和被指对象两行，分别标记创建点与结束点；再用存储期回答“多久”，用栈/堆回答常见实现中的“通常放在哪里”。随后说明空指针与悬空指针的差异；最后给出修复方向：按值返回、限制观察关系寿命、使用自动资源管理，并由 Sanitizer 辅助发现而不是依赖固定症状。

**可能连续追问**：

- 自动存储期对象是否一定在机器栈上？
- 一个自动存储期的指针能否指向动态存储期对象？
- `delete` 之后原指针会自动变成 `nullptr` 吗？
- 仅仅保存一个悬空指针值就等于已经执行了解引用吗？
- 为什么检查 `pointer != nullptr` 仍不能排除悬空？引用也会悬空吗？

**容易失分的说法**：把指针本身和所指对象混成一个“堆变量”；声称非空就安全；声称悬空一定输出垃圾或段错误；说引用永远不会悬空。

## 补充笔记：别把三种“栈/堆”混在一起

“栈”和“堆”至少出现在三个不同语境中：

1. 程序运行时常见的调用栈与内存堆；
2. 后进先出的栈数据结构；
3. 用于维护优先级的堆数据结构。

它们名称相同，但回答的问题不同。

### 一、内存组织中的调用栈与堆

先看代码，不先背位置：

```cpp
void demo() {
    int local{10};
    int* pointer{new int{20}};

    local = 11;
    *pointer = 21;

    delete pointer;
}  // local 与 pointer 在这里结束
```

这里有三个对象：

| 对象 | C++ 代码能确定的结束点 | 常见桌面实现中的位置 |
|---|---|---|
| `local` 表示的 `int` | 离开函数块 | 常在调用栈中，也可能用寄存器等方式处理 |
| 指针对象 `pointer` | 离开函数块 | 常在调用栈中 |
| `new int{20}` 创建的 `int` | 执行对应 `delete` | 默认分配机制通常使用堆相关存储 |

因此不要把 `pointer` 和 `*pointer` 混成“一个堆变量”。指针对象是局部对象，被指对象是动态对象；两者的创建点和结束点可以不同。

常见实现中，调用栈通常保存尚未返回的函数调用所需信息，堆通常提供运行期申请的存储。速度、容量和地址增长方向取决于平台、分配器、对象大小及优化，不能写成 C++17 的固定保证。

动态对象的主要用途不是“它一定更大”，而是让对象数量或存储结束时机在运行期决定。手动 `new/delete` 容易遗漏释放；工程代码通常优先让容器或智能指针管理资源，后续课程会系统学习。

### 二、数据结构中的栈

栈（stack）数据结构遵循后进先出（LIFO）：最后压入的元素最先弹出。

```cpp
#include <stack>

std::stack<int> numbers;
numbers.push(10);
numbers.push(20);
int top{numbers.top()};  // 20
numbers.pop();
```

这里的 `std::stack` 是一种容器接口，与“局部对象通常怎样放置”的调用栈不是同一个概念。

### 三、数据结构中的堆

在常见二叉堆中，元素按优先级维持父子关系；最大堆让最高优先级元素位于顶部。`std::priority_queue<int>` 默认让最大元素通过 `top()` 可见。

```cpp
#include <queue>

std::priority_queue<int> values;
values.push(20);
values.push(90);
values.push(30);
int highest{values.top()};  // 90
```

这种堆用于优先队列、Top K 等问题，与动态内存分配所说的“堆”不是同一个概念。本课程只在需要 STL 用法时继续展开，不在此扩张为算法训练。

### 四、`const int*` 与 `int* const` 到底限制谁

不要把 `*` 想成改变物理内存的“墙”。直接分别问两个问题：

1. 指针对象保存的地址能不能改？
2. 能不能通过这个指针表达式修改被指对象？

```cpp
int first{1};
int second{2};

const int* view{&first};
view = &second;   // 正确：view 可以改为指向 second
// *view = 3;     // 编译错误：不能通过 view 修改所指 int

int* const fixed{&first};
// fixed = &second;  // 编译错误：fixed 自己的地址值不能改
*fixed = 3;          // 正确：可以通过 fixed 修改 first
```

| 声明 | 指针能否改指向 | 能否通过该指针修改所指 `int` |
|---|---:|---:|
| `const int* view` | 能 | 不能 |
| `int* const fixed` | 不能 | 能，前提是所指对象本身不是 `const` |
| `const int* const fixed_view` | 不能 | 不能 |

“从变量名向外读”可以辅助解析简单声明，但真正可靠的是分别检查指针对象与被指类型上的 `const`，而不是只背“离谁近”或“星号左右”。

> [!NOTE] 问题：`const int* view` 改为指向另一个对象后，能否通过 `view` 修改新对象？

不能通过 `view` 修改，因为 `*view` 的类型仍带有 `const` 限制；改指向不会改变 `view` 的类型。不过，新对象未必是一个真正的 `const` 对象，它仍可能通过其他非 `const` 名称或指针合法修改：

```cpp
int value{1};
const int* view{&value};

// *view = 2;  // 编译错误
value = 2;     // 正确：通过非 const 名称修改
```

所以准确结论是“不能通过这条只读访问路径修改”，而不是“这个底层对象从此不能被任何方式修改”。
