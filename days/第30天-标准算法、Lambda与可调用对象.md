## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<double> forces{9.0, 12.5, 5.0, 15.0};
    const double limit = 10.0;

    std::sort(forces.begin(), forces.end());

    const auto overload_count = std::count_if(
        forces.begin(), forces.end(),
        [limit](double value) { return value > limit; });

    std::cout << "sorted:";
    for (double value : forces) {
        std::cout << ' ' << value;
    }
    std::cout << "\noverload count = " << overload_count << "\n";
}
```

| 时刻或语句 | 具体状态 | 这一步说明什么 |
|---|---|---|
| 初始 `forces` | `9, 12.5, 5, 15` | vector 保持输入顺序 |

## 第二遍：从示例推到可迁移规则

### 1. 算法负责怎么遍历，Lambda 负责判断什么

`count_if` 已经写好了从 first 到 last 的遍历。你只提供“值是否超过 limit”。这样循环机械部分和业务条件分离，代码审查时更容易核对。

### 2. 为什么区间写成 [first, last)

`last` 指向最后一个元素之后的位置，不会被解引用。空区间可直接写成 `first == last`，相邻区间也能无重叠拼接。`container.begin(), container.end()` 是最常见的一对边界。

### 3. 按值捕获与按引用捕获

`[limit]` 把当前值复制进 Lambda；`[&limit]` 保存对外层变量的引用。按引用捕获不是“更省所以更好”：Lambda 若活得比外层变量久，引用会悬空。先按生命周期和是否需要修改选择。

### 4. 算法不会自动解决容器失效

算法通过迭代器访问容器。若回调在遍历 vector 时继续插入并触发扩容，迭代器仍可能失效。标准算法减少手写错误，但不取消容器规则。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
#include <algorithm>
#include <vector>

int main() {
    std::vector<double> values{9.0, 12.5};
    double limit = 10.0;
    auto count = std::count_if(
        values.begin(), values.end(),
        [](double value) { return value > limit; });
}
```

### 根因

Lambda 的空捕获列表 `[]` 表示不能使用外层自动局部变量，因此 `limit` 无法找到。改成 `[limit]`（复制阈值）或在确实需要共享修改时使用 `[&limit]`。
