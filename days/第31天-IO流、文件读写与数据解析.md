## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <fstream>
#include <iostream>
#include <sstream>
#include <string>

int main() {
    const std::string path = "build/day-31/samples.csv";

    {
        std::ofstream output(path);
        if (!output) {
            std::cerr << "cannot create file\n";
            return 1;
        }
        output << "joint,position\n";
        output << "shoulder,1.25\n";
        output << "elbow,-0.50\n";
    }

    std::ifstream input(path);
    if (!input) {
        std::cerr << "cannot open file\n";
        return 1;
    }

    std::string line;
    std::getline(input, line);  // skip header
    while (std::getline(input, line)) {
        std::istringstream row(line);
        std::string joint;
        std::string position_text;
        if (!std::getline(row, joint, ',') ||
            !std::getline(row, position_text)) {
            std::cerr << "bad row: " << line << "\n";
            continue;
        }
        std::cout << joint << " -> " << std::stod(position_text) << "\n";
    }
}
```

## 程序一步步发生了什么

| 时刻或语句 | 具体状态 | 这一步说明什么 |
|---|---|---|
| 进入 `{}` 写文件 | `ofstream` 获得文件资源 | 先检查打开是否成功 |
| 离开 `{}` | 析构关闭并刷新文件 | RAII 管理文件句柄 |
| 第一次 `getline` | 读走表头 | `line == joint,position` |
| 循环中解析 | `istringstream` 把一行当输入流 | 逗号分开两个字段 |
| 读到文件末尾 | `getline` 返回失败状态 | 循环正常结束，不等于格式错误 |

现在再读后面的术语，它们只是给上表中已经发生的事情命名。

## 第二遍：从示例推到可迁移规则

### 1. 先判断资源是否拿到

构造 `ifstream` 不保证文件一定打开成功。路径错误、权限不足或文件不存在都会让流进入失败状态。业务代码开始读取前先写 `if (!input)`，这样错误位置清楚。

### 2. 读取成功、文件结束、格式错误是三件事

`while (getline(input, line))` 只处理成功读到的行。循环结束可能是正常 EOF，也可能是 I/O 错误；需要严格区分时再检查 `input.eof()` 与 `input.bad()`。某一行字段不足则是内容格式错误，应在解析层报告行号或原文。

### 3. 文本转数字也会失败

`stod` 可因无法转换或超出范围抛异常，也可能只转换前缀。生产解析器还应检查转换位置是否到达字符串末尾。本课先把文件层与行解析层分开，下一课系统比较错误处理策略。

### 4. 文件也是 RAII 资源

`ifstream`/`ofstream` 析构时关闭文件。用小作用域让输出流先析构，再打开同一路径读取，能清楚表达资源何时释放。

### 5. cin、operator>> 与 getline 连用的边界

`operator>>` 读取格式化值时通常把结束它的换行留在输入缓冲中，紧接着调用 `getline` 可能先读到空行。修复前先明确协议：若前一步是格式化提取，可用 `std::ws` 消耗前导空白，或统一使用 `getline` 后自行解析。输入转换失败后，必须处理流的失败状态和残留字符，不能只重复读取。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
#include <fstream>
#include <iostream>
#include <string>

int main() {
    std::ifstream input("missing.csv");
    std::string line;
    std::getline(input, line);
    std::cout << "first line: " << line << "\n";
}
```

### 根因

文件打开失败后，`getline` 也失败，`line` 仍为空；程序却打印出像正常结果一样的空行。根因是没有在第一次读取前检查 `input`。修复时应报告路径并以非零状态返回。

## 求职面试口述

可以先照下面这段说，再换成自己的话：

> 我会把文件处理拆成三层：先确认文件资源打开成功，再逐行读取并区分 EOF 与 I/O 错误，最后对每行做字段数和类型转换检查。文件流本身用 RAII 管理，离开作用域自动关闭。

1. 为什么 `while (!input.eof())` 常常会多处理一次？
