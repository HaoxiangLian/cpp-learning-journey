# 第 6 天：参数传递、引用与函数重载

预计用时：60～90 分钟  
今日目标：根据函数是否需要修改调用方、是否需要避免复制，选择按值、引用或 `const` 引用，并理解函数重载怎样选择版本。

## 1. 先运行标定与限幅程序

[parameter_passing.cpp](../examples/day-06/parameter_passing.cpp) 包含三类接口：

```cpp
double clamp(double value, double minimum, double maximum);
void apply_offset(double& reading, double offset);
void print_reading(const double& reading);
```

输出：

```text
reading: 3.25
limited reading: 3
limited retries: 3
```

`apply_offset` 修改了调用方的 `reading`，`clamp` 则只计算并返回结果。

## 2. 关键术语索引

| 术语 | 本课用它解决什么问题 |
|---|---|
| [按值传递](#按值传递) | 函数只需要输入值时怎样隔离修改 |
| [引用形参](#引用形参) | 函数怎样直接操作调用方对象 |
| [const引用形参](#const引用形参) | 怎样只读访问对象并避免复制 |
| [函数重载](#函数重载) | 同一行为怎样接受不同参数类型 |
| [重载决议](#重载决议) | 编译器怎样选中具体版本 |

### 按值传递

**按值传递会用实参的值初始化独立的形参对象。**

`clamp(double value, ...)` 中的 `value` 是本次调用自己的对象。函数修改它不会修改调用方变量。对 `int`、`double`、指针等复制成本低的小类型，按值通常简单而清楚。

### 引用形参

**`T&` 形式的引用形参是调用方某个 `T` 对象的别名，通过形参修改就是修改原对象。**

```cpp
void apply_offset(double& reading, double offset) {
    reading += offset;
}
```

调用 `apply_offset(reading, 0.75)` 后，`main` 中原来的 `reading` 从 `2.5` 变成 `3.25`。这种接口应当用于函数确实需要修改调用方的场景，并在命名上表达修改意图。

非 `const` 左值引用通常必须绑定到可修改的具名对象。[non_const_reference_error.cpp](../examples/day-06/non_const_reference_error.cpp) 试图让 `double&` 绑定到临时值 `2.5`，因此编译失败。

### const引用形参

**`const T&` 形参引用实参对象，但不允许函数通过该形参修改对象。**

它常用于只读访问复制成本较高的类对象。对本例的 `double`，工程上通常直接按值更简单；这里保留 `const double&` 只是观察语法和只读限制。第 8 天处理容器、第 13 天处理类对象时会看到更合适的使用场景。

### 函数重载

**函数重载是在同一作用域内声明多个同名函数，并让它们具有不同的参数列表。**

示例同时定义：

```cpp
double clamp(double value, double minimum, double maximum);
int clamp(int value, int minimum, int maximum);
```

它们表达相同的限幅概念，但处理不同类型。只改变返回类型不能构成合法重载。

### 重载决议

**重载决议是编译器根据实参数量、类型和所需转换，从候选函数中选择最佳可行函数的过程。**

`clamp(5, 0, 3)` 的三个实参都是 `int`，选择整数版本；`clamp(reading, 0.0, 3.0)` 使用 `double` 版本。若没有唯一最佳版本，调用会因歧义而编译失败。

## 3. 三种参数方式怎样选择

| 需求 | 常见接口 | 主要含义 |
|---|---|---|
| 只读取小型值 | `T value` | 获得独立副本，接口简单 |
| 必须修改调用方对象 | `T& value` | 明确允许修改原对象 |
| 只读访问大型对象 | `const T& value` | 不复制，也不允许通过形参修改 |

不要因为“引用更快”就把所有参数改成引用。选择首先应表达所有权和修改关系，其次才考虑已证实的复制成本。

## 4. 笔试高频点

### 预测

```cpp
void add_one(int value) { ++value; }
void add_one_ref(int& value) { ++value; }

int number{3};
add_one(number);
add_one_ref(number);
```

最终 `number` 为 `4`。第一次只修改形参副本，第二次通过引用修改原对象。

### 判断

“返回类型不同就能形成函数重载。”错误。重载决议主要依据函数名和参数列表，不能只靠期望返回类型区分。

### `const T&` 不是所有权

只读引用不负责延长所有对象的生命，也不表示它拥有资源。生命周期和所有权分别在第 10 天、第 17 天讲解。

## 5. 面试回答

### 问题：值传递、引用传递和 `const` 引用怎样选择？

> 小型且只需读取的类型通常按值传递，函数得到独立副本；需要明确修改调用方对象时使用非 `const` 引用；只读访问复制成本较高的对象时常用 `const` 引用。选择应先表达是否允许修改和是否需要复制，而不是把引用一概当作性能优化。

常见追问：

1. 为什么 `double&` 不能绑定到字面值 `2.5`？
2. 两个函数能否只靠返回类型形成重载？
