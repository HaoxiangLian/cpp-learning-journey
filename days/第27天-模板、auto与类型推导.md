## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <iostream>

template <typename T>
T clamp_value(T value, T lower, T upper) {
    if (value < lower) return lower;
    if (upper < value) return upper;
    return value;
}

int main() {
    auto integer_result = clamp_value(12, 0, 10);
    auto double_result = clamp_value(12.5, 0.0, 10.0);
    std::cout << integer_result << ' ' << double_result << '\n';
}
```

## 第二遍：从示例推到可迁移规则

### 1. 模板不是复制粘贴文本

模板在 C++ 语义和类型系统中参与查找、推导与实例化。可以把“按类型形成具体函数”作为直觉，但不要把它等同于预处理宏。

### 2. 从一次调用推导 `T`

`clamp_value(12,0,10)` 的三个实参都是 `int`，推导一致。若写 `clamp_value(12.5,0,10)`，三个位置对 `T` 给出冲突类型，可能推导失败；可统一实参类型或显式指定。

### 3. 错误为什么常很长

模板定义本身只描述模式；某个具体类型实例化后，`<`、复制或返回等操作才被检查。诊断会同时显示模板内部位置和实例化调用链，阅读时先找“用什么类型实例化”。

### 4. `auto` 不会让 C++ 变成动态类型语言

`auto value = 3.2;` 推导后 `value` 的静态类型就是 `double`。之后给它赋字符串仍然非法。

### 5. 定义为什么常放头文件

编译当前翻译单元时，实例化通常需要看到模板定义，而不只是声明。因此经典模板定义常放头文件；显式实例化可改变组织方式，今天只看位置。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
auto result = clamp_value(12.5, 0, 10);
```

### 根因

三个实参对同一个 `T` 给出 `double` 与 `int` 的冲突推导。修复为 `clamp_value(12.5, 0.0, 10.0)` 或显式说明并接受相应转换策略。

## 求职面试口述

可以先照下面这段说，再换成自己的话：

> 函数模板是生成一组具体函数的模式。调用时编译器从实参推导模板参数，按需要实例化具体函数，并检查该类型是否支持模板体中的操作。`auto` 也在编译期推导静态类型，不是运行时任意类型。模板定义常放头文件，是因为实例化点通常需要看到完整定义。

常见追问：

1. 模板定义为什么常放在头文件？
2. `auto` 会保留引用和顶层 `const` 吗，为什么要看具体写法？

合格口述不是术语数量多，而是包含“具体问题 → 代码或对象变化 → 规则 → 限制”。

- 新手先这样理解：模板定义中的类型或值占位。
- 更准确地说：`typename T` 是类型模板参数，在实例化时由具体模板实参替代。

- 新手先这样理解：本次实例化使用的具体类型或值。

**类型推导**

- 新手先这样理解：根据初始化器或函数实参确定类型。

- 回到代码定位：找到它改变了哪个对象、哪次调用或哪个构建步骤；不要脱离示例背定义。

**auto**

- 新手先这样理解：让编译器从初始化器推导静态类型。
- 更准确地说：`auto` 变量仍有固定编译期类型；引用和 `const` 是否保留取决于写法和推导规则。
