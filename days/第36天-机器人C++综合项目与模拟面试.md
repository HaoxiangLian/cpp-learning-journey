## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <algorithm>
#include <cmath>
#include <iostream>
#include <optional>
#include <string>
#include <unordered_map>
#include <vector>
#include <utility>

struct Sample {
    std::string joint;
    double position;
    double temperature;
};

std::optional<Sample> validate(Sample sample) {
    if (!std::isfinite(sample.position) ||
        sample.temperature < -40.0 ||
        sample.temperature > 125.0) {
        return std::nullopt;
    }
    return sample;
}

int main() {
    const std::vector<Sample> input{
        {"shoulder", 1.2, 45.0},
        {"elbow", -0.4, 130.0},
        {"shoulder", 1.4, 47.0},
    };

    std::vector<Sample> valid;
    std::unordered_map<std::string, int> counts;

    for (const Sample& sample : input) {
        if (auto checked = validate(sample)) {
            ++counts[checked->joint];
            valid.push_back(std::move(*checked));
        } else {
            std::cout << "rejected " << sample.joint << "\n";
        }
    }

    std::sort(valid.begin(), valid.end(),
              [](const Sample& left, const Sample& right) {
                  return left.position < right.position;
              });

    std::cout << "valid = " << valid.size() << "\n";
    std::cout << "shoulder count = " << counts.at("shoulder") << "\n";
    std::cout << "positions:";
    for (const Sample& sample : valid) {
        std::cout << ' ' << sample.position;
    }
    std::cout << "\n";
}
```

## 程序一步步发生了什么

| 时刻或语句 | 具体状态 | 这一步说明什么 |
|---|---|---|
| 输入第 1 条 | 校验成功 | 放入 valid，shoulder 计数为 1 |
| 输入第 2 条 | 温度 130 超范围 | 报告 rejected，不进入统计 |
| 输入第 3 条 | 校验成功 | shoulder 计数为 2 |
| `sort` | 按 position 升序排列有效样本 | 结果 1.2, 1.4 |
| 输出报告 | 有效数、按关节计数、位置序列 | 可作为测试的可观察结果 |

## 第二遍：从示例推到可迁移规则

### 1. 项目主线必须一口气讲清

输入是三条 Sample；validate 拒绝非有限位置和温度越界；有效样本进入 vector，按 joint 在 unordered_map 计数，再排序并输出。先讲数据如何流动，再讲每个语言特性。

### 2. 每个选择都要连接约束

`vector` 因为结果需要连续遍历与排序；`unordered_map` 因为按名称计数且不要求有序输出；`optional` 因为校验只有有值/无值两种结果。若需要详细错误原因，就升级结果类型，不把 optional 说成万能方案。

### 3. 从演示程序升级为求职项目

下一步把 Sample、validate 和报告拆成库；用 CMake 构建；添加单元测试覆盖 NaN、温度边界、空输入与缺键；文件输入报告行号；CI 运行警告、测试和 Sanitizer。README 写架构、命令、示例输出和已知限制。

### 4. 模拟面试按证据回答

回答“为什么这样设计”时引用实际代码、测试或故障实验；回答“还能怎么改”时指出当前约束变化后才值得做的改进。不要把术语堆成答案，也不要声称小项目已经适合所有实时机器人系统。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
#include <numeric>
#include <vector>

double average(const std::vector<double>& values) {
    const double sum = std::accumulate(values.begin(), values.end(), 0.0);
    return sum / values.size();
}

// 空输入时 size() 为 0，接口没有定义失败方式。
```

### 根因

根因不是“浮点数偶尔不准”，而是接口没有为空输入定义契约。可返回 `optional<double>`，或把非空作为前置条件并在更早层保证；求职项目应为选择写测试和说明。

调试时固定按这个顺序记录：

1. 我期望看到什么？
2. 实际最早出现的不同是什么？
3. 哪条语言规则或接口契约被违反？
4. 最小修改是什么？
5. 修改后用什么输入证明问题真的修好？

## 求职面试口述

可以先照下面这段说，再换成自己的话：

> 这个项目把遥测样本经过校验、统计、排序和报告。容器与错误表示都由访问方式和失败需求决定；我用测试覆盖边界，用 CMake 保证构建复现。当前示例是离线单线程管线，若用于实时系统，还需明确时延、并发、内存分配和故障恢复约束。

常见追问：

1. 请用 60 秒讲清数据从输入到输出的路径。
2. 为什么计数用 unordered_map、结果用 vector？
3. 若接入实时采集线程，当前设计首先要补哪些约束？

合格口述不是术语数量多，而是包含“具体问题 → 代码或对象变化 → 规则 → 限制”。
