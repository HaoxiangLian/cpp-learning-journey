## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<double> samples;
    samples.reserve(4);
    samples.push_back(1.0);
    samples.push_back(2.0);

    auto first = samples.begin();
    std::cout << *first << '\n';

    samples.push_back(3.0);
    std::cout << *first << '\n'; // reserve 足够时本例仍有效
}
```

## 第二遍：从示例推到可迁移规则

### 1. 先按访问模式选容器

`vector` 适合连续存储、随机访问和尾部增长，是默认顺序容器；`deque` 支持两端高效插入且不保证整体连续；`list` 是节点式双向链表，随机访问慢且额外开销大。不要因为“插入快”就默认选择链表。

### 2. 大小与容量

`size()` 是已经存在的元素数；`capacity()` 是当前存储可容纳数。读取 `samples[3]` 的合法性只看大小，不看容量。

### 3. 失效规则必须绑定具体操作

`vector::push_back` 若重分配则全部失效；未重分配时尾后迭代器会变化，插入点规则也需查接口保证。最安全做法是修改后重新取得位置，或保存稳定索引并再次检查。

### 4. 迭代器不是裸指针的同义词

`vector` 迭代器常像指针，但标准只保证其迭代器语义；`list` 迭代器显然不是连续地址指针。算法通过统一迭代器接口工作。

### 5. 用实验证明重分配

记录 `data()`、`size()` 和 `capacity()`，不断 `push_back`。当 `data()` 变化时说明底层存储地址改变；绝不能在变化后解引用旧指针来“看看会怎样”。

### 6. 固定大小序列先考虑 array

`std::array<T, N>` 把元素个数写进类型，元素连续存储，支持 `size()`、迭代器和标准算法；它没有 `push_back`。大小在编译时固定且需要值语义时，它通常比原生数组更容易组合；运行时长度或需要增长时仍优先 `vector`。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
std::vector<int> values{1, 2, 3};
int& first = values[0];
values.push_back(4); // 可能重分配
std::cout << first;  // 可能使用失效引用
```

### 根因

是否重分配取决于之前容量，代码不能靠偶然剩余容量保证。需要在修改后重新获取引用，或预先 `reserve` 并确保上限，同时仍遵守其他失效规则。

## 求职面试口述

可以先照下面这段说，再换成自己的话：

> 容器选择看访问模式、修改模式、内存布局和失效规则。`vector` 连续存储、随机访问快，是默认选择；增长可能重分配，导致旧指针、引用和迭代器全部失效。`size` 是现有元素数，`capacity` 只是可容纳数。迭代器是否合法必须结合具体容器和操作判断。

1. `vector` 的 `size` 与 `capacity` 有什么区别？
