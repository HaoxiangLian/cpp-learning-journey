## 第一遍：先跑、再沿着对象变化（必学）

```cpp
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <queue>
#include <thread>

int main() {
    std::queue<int> samples;
    std::mutex mutex;
    std::condition_variable ready;
    bool done = false;

    std::thread consumer([&] {
        while (true) {
            std::unique_lock<std::mutex> lock(mutex);
            ready.wait(lock, [&] { return !samples.empty() || done; });

            if (samples.empty() && done) {
                break;
            }

            const int value = samples.front();
            samples.pop();
            lock.unlock();
            std::cout << "processed " << value << "\n";
        }
    });

    for (int value : {10, 20, 30}) {
        {
            std::lock_guard<std::mutex> lock(mutex);
            samples.push(value);
        }
        ready.notify_one();
    }

    {
        std::lock_guard<std::mutex> lock(mutex);
        done = true;
    }
    ready.notify_one();
    consumer.join();
}
```

## 程序一步步发生了什么

| 时刻或语句 | 具体状态 | 这一步说明什么 |
|---|---|---|
| 消费者队列为空 | `wait` 原子地解锁并休眠 | 不忙等 |
| 生产者 push 10 | 持锁修改队列 | 解锁后通知 |
| 消费者醒来 | 重新持锁并检查谓词 | 取出一个元素 |
| 解锁后打印 | 缩短临界区 | I/O 不占用队列锁 |
| `done = true` 且队列空 | 消费者退出循环 | 主线程 join |

现在再读后面的术语，它们只是给上表中已经发生的事情命名。

## 第二遍：从示例推到可迁移规则

### 1. 先减少共享，再考虑加锁

线程只操作自己的局部数据最简单。确实需要共享队列时，明确 mutex 同时保护 `samples` 和 `done`，任何访问都遵守同一规则。只保护写、不保护读仍然是错误。

### 2. 数据竞争不是普通的结果先后不同

C++ 中数据竞争会导致未定义行为，编译器不需要保证你看到某个“只是少算一点”的结果。竞争条件是更广的逻辑概念；即使每次访问都加锁，错误的检查—再执行顺序仍可能产生竞态。

### 3. condition_variable 为什么总带谓词

通知可能早于等待，也可能出现伪唤醒，因此醒来不能假设条件成立。`wait(lock, predicate)` 会在持锁状态下反复检查 `!samples.empty() || done`。

### 4. 锁的范围和退出协议

只在访问共享队列时持锁，取出值后先解锁再做慢 I/O。程序还需要 `done` 协议，否则消费者不知道以后是否还会有数据。所有可 join 的 thread 在析构前必须 join 或 detach；通常优先 join。

### 5. 用工具寻找并发证据

GCC 或 Clang 支持时，可用 `-fsanitize=thread -g` 构建故障计数器，让 ThreadSanitizer 报告冲突访问。工具报告是定位线索，不代替共享状态协议；修复后还要检查是否所有读写都遵守同一同步规则。

## 故障实验：故意让程序出错

先不要运行，写下你认为它会在“编译、链接、运行或结果”中的哪一阶段失败。

```cpp
#include <iostream>
#include <thread>

int main() {
    int counter = 0;
    auto work = [&] {
        for (int i = 0; i < 100000; ++i) {
            ++counter;
        }
    };
    std::thread a(work);
    std::thread b(work);
    a.join();
    b.join();
    std::cout << counter << "\n";
}
```

### 根因

两个线程无同步地读—改—写同一个 `counter`，构成数据竞争，行为未定义；结果不是简单保证在 100000 到 200000 之间。可用 mutex 保护复合操作，或在适合的计数场景使用 `std::atomic<int>`，并明确所需内存语义。
