### 5. 先形成一个求职可用回答

> 所有权先回答谁保证资源存活并最终释放。默认动态对象所有者是 `unique_ptr`；只有多个独立组件确实共同延长生命周期时才用 `shared_ptr`；不承担存活责任的共享观察用 `weak_ptr`，一般非拥有访问可用引用或裸指针。智能指针不是越多越安全，关键是让类型准确表达责任关系并避免控制块重复和所有权环。

## 1. 完整知识地图

智能指针不是“更安全的裸指针”这么简单。它位于下面这条完整资源管理链路中：

```text
确定资源的存活责任
    ├─ 不拥有：引用 / 裸指针 / weak_ptr
    └─ 拥有
        ├─ 独占：unique_ptr
        │   └─ 所有权可通过移动转交
        └─ 共享：shared_ptr
            ├─ 复制会增加共享所有者
            ├─ 最后一个共享所有者消失时销毁对象
            └─ weak_ptr 观察共享对象而不延长其生命周期

创建对象 → 建立所有权 → 访问对象 → 转移或共享所有权
        → 所有者结束 → 销毁对象 → 释放存储
```

这张图描述的是本主题的完整方向；今天会掌握常用、安全的主干规则，但不是把智能指针全部 API 都讲完。

## 3. 所有权先于指针类型

新手可以先这样复述[所有权](#术语-d23-01-所有权)：**谁保证资源活着，谁最终负责释放资源。**承担这项责任的对象称为[所有者](#术语-d23-02-所有者)。专业上，所有权是释放责任和有效期约束，不是“谁能访问对象”；能访问对象的名称可能只是[观察者](#术语-d23-03-观察者)。

```cpp
auto owner = std::make_unique<int>(42); // owner 是所有者
int* observer = owner.get();            // observer 不拥有对象
std::cout << *observer << '\n';         // owner 尚未结束，因此有效
```

此时真实状态可写成：

```text
unique_ptr owner ──拥有──> int 对象 42
裸指针 observer ──观察──> 同一个 int 对象
```

`observer` 不会延长 `int` 的生命周期。若 `owner.reset()`，对象被销毁、动态存储被解分配，`observer` 随即成为悬空指针。把它设为 `nullptr` 只能防止以后误用这个名称，不能“恢复”已经结束的对象。

这里使用的[智能指针](#术语-d23-04-智能指针) 是标准库类模板对象，而不是一种新的内建指针类型。选择规则：

1. 没有存活责任：优先引用；允许为空或需要重新指向时使用裸指针。
2. 唯一存活责任：`unique_ptr`。
3. 确有多个独立组件共同延长生命周期：`shared_ptr`。
4. 需要观察共享对象但不能延长其生命周期：`weak_ptr`。

## 4. `unique_ptr`：默认的动态对象所有者

新手可把 [`unique_ptr`](#术语-d23-05-unique_ptr) 复述为：**同一时刻只允许一个智能指针负责这个对象。**专业定义是：它是不可复制、可移动的独占所有者；非空所有者结束时通过删除器处理受管对象。

```cpp
auto first = std::make_unique<std::string>("arm");
// auto copy = first;              // 编译错误：复制操作被删除
auto second = std::move(first);    // 所有权转移
```

[`make_unique`](#术语-d23-06-make_unique) 是首选创建方式。上述移动后的真实状态是：

```text
first  == nullptr
second ──独占拥有──> string 对象 "arm"
```

这次[所有权转移](#术语-d23-07-所有权转移) 不会复制 `string` 对象，也不会销毁它。`unique_ptr` 的[移后状态](#术语-d23-08-移后状态) 有明确保证：来源为空；不能把这个保证随意推广到所有类型。

### 4.1 `get`、`release` 与 `reset` 不是同一操作

- [`get()`](#术语-d23-09-get) 返回观察用裸指针，智能指针仍拥有对象；
- [`release()`](#术语-d23-10-release) 交出裸指针，智能指针停止管理，但对象不会被删除；
- [`reset()`](#术语-d23-11-reset) 结束当前所有权，当前对象通常立刻销毁。

```cpp
auto value = std::make_unique<int>(7);
int* view = value.get();

value.reset();  // 销毁 int 并释放存储；view 现在悬空
```

`release()` 只应出现在明确接入另一套所有权协议的边界：

```cpp
int* raw = value.release();
// 从这一刻起，必须立刻把 raw 交给另一个所有者或正确 delete。
```

### 4.2 数组与自定义删除器

`unique_ptr<T[]>` 是标准库提供的数组特化，使用 `delete[]`。但它不保存元素个数，也没有 `size()`、迭代器和扩容操作；多数业务数组仍应优先使用 `vector<T>`。第 28 天会在容器语境中补齐。

[自定义删除器](#术语-d23-21-自定义删除器) 让所有权结束时执行其他协议，例如关闭 C API 句柄。今天能识别这个位置即可；第 25 天结合异常安全深入。

## 5. `shared_ptr`：确有共同存活责任时使用

新手可把 [`shared_ptr`](#术语-d23-12-shared_ptr) 复述为：**多个所有者共同投票让对象继续存活，最后一个所有者离开时对象销毁。**专业上，复制 `shared_ptr` 会加入同一[共享所有权组](#术语-d23-13-共享所有权组)，最后一个共享所有者释放时销毁受管对象。

```cpp
auto first = std::make_shared<std::string>("sensor");
{
    auto second = first;
    std::cout << first.use_count() << '\n'; // 2
}
std::cout << first.use_count() << '\n';     // 1
```

[`make_shared`](#术语-d23-16-make_shared) 把对象创建和共享所有权建立放在一个表达式中，通常优于先写裸 `new`。标准库实现通过[控制块](#术语-d23-14-控制块) 保存删除信息和计数；具体布局不是 C++ 语言保证。

[强引用计数](#术语-d23-15-强引用计数) 归零时受管对象销毁。`use_count()` 适合教学观察和诊断，却不应成为日常业务分支的核心：它只是调用瞬间的结果，并发环境下随后可能改变。

### 5.1 不要从同一个裸指针建立两组所有权

```cpp
int* raw = new int{42};
std::shared_ptr<int> first{raw};
std::shared_ptr<int> second{raw}; // 错误：不知道 first 的控制块
```

这不是共享，而是[双重所有权](#术语-d23-20-双重所有权)：两个独立控制块最终都对同一地址执行 `delete`，程序产生未定义行为。正确方式是先建立一个所有者，再复制它：

```cpp
auto first = std::make_shared<int>(42);
auto second = first;
```

不要把“指针值相同”等同于“共享同一所有权组”。

## 6. `weak_ptr`：观察共享对象

新手可把 [`weak_ptr`](#术语-d23-17-weak_ptr) 复述为：**它记得共享对象，但不要求对象为了自己继续活着。**专业上，它关联共享所有权组但不增加强引用计数，因此对象可以先于 `weak_ptr` 销毁。

不能直接解引用 `weak_ptr`，因为“检查还活着”和“开始访问”之间对象可能死亡。应使用 [`lock()`](#术语-d23-18-lock)：它在对象仍存活时返回一个临时 `shared_ptr`，否则返回空指针。

```cpp
std::weak_ptr<int> observer;
{
    auto owner = std::make_shared<int>(9);
    observer = owner;

    if (auto locked = observer.lock()) {
        std::cout << *locked << '\n';
    }
}

if (auto locked = observer.lock()) {
    std::cout << *locked << '\n';
} else {
    std::cout << "expired\n";
}
```

`expired()` 可查询状态，但若之后还要访问，仍应直接 `lock()` 并检查返回值，让检查与取得临时所有权成为一个操作。

## 7. 共享所有权环

新手可把[所有权环](#术语-d23-19-所有权环) 复述为：**对象互相用 `shared_ptr` 拉住对方，外部都离开了，内部计数仍不为零。**

```cpp
struct Node {
    std::shared_ptr<Node> next;
};

auto first = std::make_shared<Node>();
auto second = std::make_shared<Node>();
first->next = second;
second->next = first;
```

离开作用域前，每个节点都有一个外部所有者和一个来自另一节点的所有者；外部所有者消失后，每个节点仍被对方拥有，析构不会开始。解决方法不是“手动把计数减一”，而是重新表达关系：只有真正承担存活责任的边使用 `shared_ptr`，反向导航或缓存边使用 `weak_ptr`。

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> previous;
};
```

## 8. 真实创建、执行与销毁过程

以 `std::make_unique<Motor>("joint-A")` 为例，抽象但准确的可观察过程是：

1. 为 `Motor` 获得适当存储；
2. 在该存储中构造 `Motor` 对象；
3. 返回拥有该对象的 `unique_ptr<Motor>`；
4. 移动只转交保存的所有权状态，不复制 `Motor`；
5. 最后一个独占所有者 `reset()` 或析构时，先析构 `Motor`，再按删除器协议解分配存储。

对 `shared_ptr`，对象与控制块的具体分配布局取决于实现，但可观察规则保持不变：共享所有者数量归零时受管对象销毁；所有弱观察也消失后，管理状态才能完全释放。

源码仍需经过第 4 天的完整构建链路：

```text
源文件 → 预处理 → 狭义编译 → 汇编 → 目标文件 → 链接
      → 可执行文件 → 操作系统装载与启动 → 执行 main
```

智能指针不会把这条链路缩成一个步骤；其模板代码在翻译单元中实例化，链接后才形成完整程序。

这段输出把构造、观察、独占转移、共享计数、弱观察和析构顺序落到了真实执行过程。

## 10. 错误实验

### 10.1 复制 `unique_ptr`：编译期错误

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
  examples/day-23/unique_copy_error.cpp -o /tmp/day23-copy
```

编译器应指出 `unique_ptr` 的复制构造操作被删除。所有权规则在编译期阻止了两个独占所有者。

### 10.2 悬空观察者：运行期未定义行为

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  examples/day-23/dangling_observer.cpp -o /tmp/day23-dangling
/tmp/day23-dangling
```

`owner.reset()` 后对象已销毁；再解引用裸观察者会由 AddressSanitizer 报告释放后使用。Sanitizer 是检测工具，不会把未定义行为变成标准规定的固定结果。

### 10.3 两个控制块：重复释放

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  examples/day-23/double_control_block.cpp -o /tmp/day23-double
/tmp/day23-double
```

程序会在两个独立 `shared_ptr` 析构时尝试两次释放同一对象。工具通常报告 double-free；语言层面的结论是未定义行为。

### 10.4 所有权环：逻辑资源泄漏

```bash
g++ -std=c++17 -Wall -Wextra -Wpedantic \
  examples/day-23/ownership_cycle.cpp -o /tmp/day23-cycle
/tmp/day23-cycle
```

输出包含两个 `construct`，却没有 `destroy`：这不是析构顺序变化，而是环中的强引用计数没有归零。

## 11. 选择指南与易混边界

| 需求 | 首选表达 | 关键约束 |
|---|---|---|
| 一个组件独占动态对象 | `unique_ptr<T>` | 可移动，不可复制 |
| 函数调用期间必定存在且不可空 | `T&` / `const T&` | 调用方保证生命周期 |
| 可空的短期非拥有访问 | `T*` / `const T*` | 使用前验证非空且仍有效 |
| 多个组件确实共同维持存活 | `shared_ptr<T>` | 复制意味着增加所有者 |
| 观察共享对象但不维持存活 | `weak_ptr<T>` | 使用前 `lock()` |

易混概念：

- 指针是否为 `const` 与是否拥有对象无关；
- `shared_ptr<const T>` 约束通过该指针修改 `T`，不代表只有一个所有者；
- `const shared_ptr<T>` 不能重新指向，但仍可通过它修改 `T`；
- 形参按值接收 `shared_ptr` 会增加一次共享所有权；只观察时通常接收 `T&`、`T*`，或在需要表达共享句柄身份时接收 `const shared_ptr<T>&`；
- 返回 `unique_ptr` 通常由移动或复制消除完成所有权转移，不需要裸 `new`。

业务类用智能指针成员管理资源，通常可遵循 [Rule of Zero](#术语-d23-22-rule-of-zero)，无需手写析构、复制和移动。但含 `unique_ptr` 的类会自然不可复制；若业务确实需要深复制，仍要显式设计复制语义。

## 附录：关键术语卡（查阅用）

###### 术语-d23-01-所有权

**专业术语（资源管理概念）**：所有权是程序对“哪个对象或组件负责维持某项资源有效，并在责任结束时执行释放协议”的设计约束。C++ 语言没有一个名为“所有权”的内建运行时属性；智能指针类型把常见所有权约束编码进类型和操作。

###### 术语-d23-02-所有者

**专业术语（资源管理概念）**：所有者是承担资源释放责任的对象或组件。一个所有者结束生命周期、被赋新资源或显式重置时，必须按其协议处理当前资源。

###### 术语-d23-03-观察者

**专业术语（工程术语）**：观察者持有访问资源所需的引用、指针或句柄，但不拥有资源。观察者的每次使用都必须发生在资源仍有效的期间；裸指针本身不会记录或检查这一条件。

###### 术语-d23-04-智能指针

**C++ 标准库术语**：智能指针是行为类似指针的类模板；本单元特指 `<memory>` 中的 `unique_ptr`、`shared_ptr` 和 `weak_ptr`。前两者在析构等操作中按协议管理受管对象，`weak_ptr` 表达对共享所有权组的非拥有观察。

###### 术语-d23-05-unique_ptr

**C++ 标准库类型**：`std::unique_ptr<T, D>` 是不可复制、可移动的所有者类型，使用删除器 `D` 管理一个 `T` 对象或空状态。非空 `unique_ptr` 被销毁或重置时调用删除器。

###### 术语-d23-06-make_unique

**C++ 标准库函数模板**：`std::make_unique<T>(args...)` 用转发后的参数创建 `T`，返回拥有它的 `unique_ptr<T>`。它把分配、构造与所有权建立组合在一个表达式中。

###### 术语-d23-07-所有权转移

**资源管理术语**：所有权转移是把释放责任从一个所有者移交给另一个所有者。`unique_ptr` 通过移动构造或移动赋值实现转移，复制操作被删除。

###### 术语-d23-08-移后状态

**C++ 标准术语相关规则**：标准库对象被移动后通常处于“有效但未指定”的状态，除非该类型给出更强保证。`unique_ptr` 给出明确保证：被移动来源变为空。

###### 术语-d23-09-get

**C++ 标准库成员函数**：智能指针的 `get()` 返回其保存的指针，不改变所有权。返回值通常只应作为短期观察者使用。

###### 术语-d23-10-release

**C++ 标准库成员函数**：`unique_ptr::release()` 返回保存的指针并令自身变为空，不调用删除器。调用方必须立即把责任交给其他所有者或正确完成释放，否则会泄漏。

###### 术语-d23-11-reset

**C++ 标准库成员函数**：`reset(p)` 先按协议处理当前受管对象，再保存 `p`；无参数 `reset()` 令智能指针变为空。对非空 `unique_ptr` 而言，这通常导致当前对象立即销毁。

###### 术语-d23-12-shared_ptr

**C++ 标准库类型**：`std::shared_ptr<T>` 表达共享所有权。共享同一所有权组的最后一个 `shared_ptr` 释放所有权时，受管对象被销毁。

###### 术语-d23-13-共享所有权组

**教学用工程术语**：共享所有权组是共享同一所有权信息的一组 `shared_ptr`/`weak_ptr`。这是为准确解释关系使用的名称，不是一个可在源码中声明的 C++ 类型。

###### 术语-d23-14-控制块

**C++ 标准库实现模型术语**：控制块保存共享计数、弱计数、删除器等管理信息。标准库接口保证可观察语义；控制块的具体内存布局、计数类型和分配方式属于实现细节，不是语言保证。

###### 术语-d23-15-强引用计数

**共享所有权术语**：强引用计数表示共享所有权者的数量。`use_count()` 可观察一个瞬时值；不能仅凭它在并发程序中作“随后仍安全”的判断。

###### 术语-d23-16-make_shared

**C++ 标准库函数模板**：`std::make_shared<T>(args...)` 创建 `T` 并返回共享所有者。常见实现将对象和控制块合并分配，但合并方式不是本单元依赖的语言级保证。

###### 术语-d23-17-weak_ptr

**C++ 标准库类型**：`std::weak_ptr<T>` 引用一个共享所有权组但不拥有对象，不增加强引用计数。对象可能在 `weak_ptr` 仍存在时销毁。

###### 术语-d23-18-lock

**C++ 标准库成员函数**：`weak_ptr::lock()` 原子地检查受管对象是否仍存在；存在则返回共享它的 `shared_ptr`，否则返回空 `shared_ptr`。

###### 术语-d23-19-所有权环

**资源管理术语**：所有权环是共享所有者构成的有向环，使环内对象即使不再被外部使用，强引用计数仍不能降到零。应把不承担存活责任的边改为 `weak_ptr`。

###### 术语-d23-20-双重所有权

**错误模式术语**：双重所有权是两个独立所有权机制都准备释放同一资源。两个分别从同一裸指针构造的 `shared_ptr` 通常形成两个控制块，最终造成重复释放和未定义行为。

###### 术语-d23-21-自定义删除器

**C++ 标准库概念**：删除器是智能指针在结束所有权时调用的可调用对象。它可用于文件句柄、C API 资源等非 `delete` 协议；`unique_ptr` 的删除器属于其类型的一部分。

###### 术语-d23-22-rule-of-zero

**C++ 工程准则**：Rule of Zero 建议业务类通过 `string`、容器和智能指针等 RAII 成员拥有资源，从而不手写析构、复制和移动特殊成员，让编译器生成正确组合行为。
