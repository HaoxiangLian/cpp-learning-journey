# C++ 术语表

本文件保存课程中每个术语的唯一规范定义。每日讲义不单列术语卡，而是在对应核心机制首次使用术语时重复同一句定义并链接这里；直观模型只帮助理解，不构成另一份定义。

## 第 1 天

### 函数（function）

- **定义**：函数是可被调用以执行一组语句的程序实体，并具有确定的名称或调用方式、输入形式和返回类型。
- **决定什么**：决定一次调用允许提供什么输入、执行什么语句以及返回什么类型。
- **不决定什么**：不单独决定调用一定成功，也不决定输入对象的生命周期。
- **最小示例**：

  ```cpp
  int status_code() {
      return 7;
  }
  ```

- **常见误解**：把函数声明当作“函数已经实现”。只有声明而缺少被需要的定义，通常会在链接阶段失败。

### 声明（declaration）

- **定义**：声明把一个名称引入或重新引入程序，并说明该名称所指实体的必要属性。
- **决定什么**：决定当前位置之后的代码能否按声明的信息引用该名称。
- **不决定什么**：声明不一定提供函数体，也不一定产生一个可供链接的实体；有些声明同时也是定义。
- **最小示例**：

  ```cpp
  int status_code();
  ```

- **常见误解**：认为“声明和定义绝对互斥”。定义本身也是一种声明，只是它还提供了定义所需的完整内容。

### 定义（definition）

- **定义**：定义是一种声明，它为被定义的实体提供程序所要求的完整定义；例如函数定义提供函数体。
- **决定什么**：决定程序在需要该实体的定义时是否拥有可用实现。
- **不决定什么**：不保证任意数量的重复定义都合法；不同实体和 `inline` 等规则有各自条件。
- **最小示例**：

  ```cpp
  int status_code() {
      return 7;
  }
  ```

- **常见误解**：把头文件中的函数声明误认为函数定义，因此忘记把实现文件加入构建目标。

### 编译（compilation）

- **定义**：在本课程的构建语境中，编译是把每个源文件及其包含内容分别翻译并进行语法、类型等检查，生成可供后续组合使用结果的过程。
- **决定什么**：决定单个编译输入能否通过语言规则检查，并产出后续构建所需信息。
- **不决定什么**：不能单独证明跨文件引用都有定义，也不保证程序运行逻辑正确。
- **最小示例**：

  ```bash
  c++ -std=c++17 -Wall -Wextra -Wpedantic -c status.cpp
  ```

- **常见误解**：把所有构建失败都叫编译错误。缺少另一个文件中的函数定义通常是链接错误。
- **标准边界**：C++ 标准描述翻译过程，但不要求实现必须生成名为 `.o` 或 `.obj` 的中间文件。

### 链接（linking）

- **定义**：在常见 C++ 构建模型中，链接是组合分别翻译得到的结果和所需库，并解析跨文件实体引用以形成可执行程序或库的过程。
- **决定什么**：决定所需跨文件符号能否找到相容定义并被组合。
- **不决定什么**：不验证所有运行路径的业务逻辑，也不保证程序运行时不会失败。
- **最小示例**：

  ```bash
  c++ main.o status.o -o day01_example
  ```

- **常见误解**：看到“undefined reference”就认为源码一定存在语法错误；它更常表示实现未参与链接或签名不一致。
- **标准边界**：C++ 标准不要求存在独立的链接器进程；“目标文件—链接器”是主流实现模型。

### 未定义行为（undefined behavior, UB）

- **定义**：未定义行为是 C++ 标准对其结果不作任何要求的行为。
- **决定什么**：决定不能依据 C++ 标准预测该次执行的结果，也不能把某次观察到的现象当作保证。
- **不决定什么**：不决定程序必然崩溃、必然段错误或必然出现某个输出。
- **最小示例（故意错误，不进入构建）**：

  ```cpp
  int* pointer = nullptr;
  *pointer = 1;  // 解引用空指针：未定义行为
  ```

- **常见误解**：把“我的机器上输出正常”当作行为已定义，或把 UB 直接等同于必然崩溃。

## 第 2 天

### 对象（object）

- **定义**：对象是程序执行期间占据一段存储、具有类型，并可表示值的实体。
- **决定什么**：对象的类型决定可用操作和表示值时必须遵守的语言规则。
- **不决定什么**：对象不一定有名称；C++ 标准也不保证某个普通对象一定放在寄存器、栈或其他特定硬件区域。
- **最小示例**：

  ```cpp
  int sample_count{0};  // sample_count 所指的是一个 int 对象
  ```

- **常见误解**：把“对象”只理解为类的实例。`int`、`double` 等基本类型也能创建对象。

### 变量（variable）

- **定义**：变量是由声明引入的具名对象或具名引用；引用是一种别名机制，将在第 6 天展开。
- **决定什么**：变量提供一个名称，使代码可以引用相应对象或引用所绑定的实体。
- **不决定什么**：变量不是“可以随时改变的值”的同义词；`const` 变量也仍然是变量。
- **最小示例**：

  ```cpp
  const int sensor_id{12};  // sensor_id 是变量，所指对象不可被普通赋值修改
  ```

- **常见误解**：认为变量必须可变，或者认为对象和变量是完全相同的概念。

### 值（value）

- **定义**：值是对象能够表示或表达式求值能够产生的抽象信息。
- **决定什么**：值参与运算、比较和输出时决定相应结果。
- **不决定什么**：值本身不等于保存它的对象，也不等于对象在具体机器上的字节排列。
- **最小示例**：

  ```cpp
  int sample_count{3};  // 对象 sample_count 当前表示值 3
  ```

- **常见误解**：把变量名称、对象和对象当前保存的值当作同一个东西。

### 类型（type）

- **定义**：类型是 C++ 对对象、引用、函数和表达式进行分类的规则系统，它规定可表示的值、允许的操作及相关语义约束。
- **决定什么**：决定哪些操作合法，以及操作如何解释；例如整数类型与浮点类型具有不同的表示和运算规则。
- **不决定什么**：只写 `int` 并不能跨所有实现保证它恰好占 4 字节；具体大小受标准最低要求和实现选择共同约束。
- **最小示例**：

  ```cpp
  int sample_count{3};
  double temperature_celsius{21.75};
  ```

- **常见误解**：认为类型只是“占多少字节”，忽略它还决定合法操作和表达式语义。

### 初始化（initialization）

- **定义**：初始化是在对象被创建时确定其初始状态的过程。
- **决定什么**：决定对象从创建开始拥有什么初始值或状态，以及使用哪种初始化规则。
- **不决定什么**：初始化不是对象创建后的普通赋值；带 `=` 的声明也可能仍然是初始化。
- **最小示例**：

  ```cpp
  int sample_count{0};  // 创建对象并初始化为 0
  ```

- **常见误解**：看到 `int count = 0;` 中的 `=` 就把它叫作赋值。这里整个声明执行的是初始化。

### 赋值（assignment）

- **定义**：赋值是在对象已经完成初始化之后，用赋值运算修改其当前值或状态的操作。
- **决定什么**：决定现有可修改对象在操作完成后的新值或状态。
- **不决定什么**：赋值不会再次创建同一个对象，也不能用于修改不可赋值的 `const` 对象。
- **最小示例**：

  ```cpp
  int sample_count{0};
  sample_count = 1;  // 对已存在的对象赋值
  ```

- **常见误解**：认为初始化和赋值只是两种等价写法；对于类对象，两者甚至可能调用不同的成员函数，第 9—10 天会展开。

### const 限定（const qualification）

- **定义**：`const` 限定表示程序不得通过相应对象的普通访问方式修改其值或状态。
- **决定什么**：决定哪些修改表达式会被语言规则拒绝，并要求 `const` 对象在创建时获得可用初始状态。
- **不决定什么**：`const` 不自动表示值在编译期已知，也不保证实现必须把对象放入只读硬件内存。
- **最小示例**：

  ```cpp
  const int sensor_id{12};
  ```

- **常见误解**：把 `const` 直接等同于“编译期常量”。运行时得到的值也可以用于初始化某些 `const` 对象。
