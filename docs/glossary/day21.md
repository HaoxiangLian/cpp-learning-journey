# 第 21 天术语：线程、共享数据与同步

### 线程与 `join`（thread and join）

- **定义**：线程是程序中可与其他执行流并发推进的一条执行流；对 `std::thread` 调用 `join()` 会等待其关联线程结束，并在成功返回后使该线程已经完成的操作先于调用线程随后的操作。
- **决定什么**：它决定调用线程何时确认工作线程已经结束，以及何时能按同步关系读取工作线程留下的结果。
- **不决定什么**：创建线程不保证它立刻运行，也不保证两个线程的具体交错顺序；`join()` 也不替共享阶段中的每次并发访问加锁。
- **最小示例**：`std::thread worker{[&] { result = 21; }}; worker.join();`
- **常见误解**：认为线程对象析构会自动等待，或把一次 `join()` 当成所有共享访问都自动安全。

### 数据竞争、互斥量与作用域锁（data race, mutex and scoped lock）

- **定义**：数据竞争是不同线程并发访问同一内存位置、至少一个访问是写入且这些冲突访问之间没有合适同步的情形；互斥量让同一时刻至多一个持锁线程进入受保护区域，作用域锁对象把取得和释放该锁绑定到自身生命周期。
- **决定什么**：它们决定冲突访问是否被排成互不重叠的受保护操作，并让同一互斥量前一次解锁之前的操作对后一次成功加锁后的操作可见。
- **不决定什么**：互斥量不自动识别应保护哪些数据，不保证公平调度；不同线程各锁不同互斥量也不能保护同一个共享对象。
- **最小示例**：`std::lock_guard<std::mutex> lock{count_mutex}; ++count;`
- **常见误解**：认为单条 `++count` 天然原子，或认为只要代码里出现任意一把锁就不会发生数据竞争。

### 死锁与锁顺序（deadlock and lock ordering）

- **定义**：死锁是多个执行流各自等待只有其他等待者才能促成的条件而都无法继续的状态；固定锁顺序或让 `std::scoped_lock` 协调取得多把互斥量可以避免常见的循环等待。
- **决定什么**：统一的锁策略能消除“甲持有 A 等 B、乙持有 B 等 A”这一类循环等待条件。
- **不决定什么**：使用互斥量不自动杜绝死锁；避免死锁也不等于没有数据竞争、饥饿或业务逻辑错误。
- **最小示例**：`std::scoped_lock lock{left_mutex, right_mutex};`
- **常见误解**：认为每个线程最终都会解锁，所以相反顺序取得多把锁也一定能继续。

### 原子操作与线程间可见性（atomic operation and inter-thread visibility）

- **定义**：对 `std::atomic<T>` 的单次原子操作不会被其他线程观察为中途撕裂；满足相应内存顺序的发布与获取操作还能建立同步，使发布前的写入对获取后的读取可见。
- **决定什么**：它决定同一个原子对象的单次访问是否不可分割，以及在匹配同步关系下哪些先前写入可由另一线程可靠观察。
- **不决定什么**：一个原子变量不会自动把周围多个普通操作合成不可分割事务，也不会自动替所有共享对象建立正确协议。
- **最小示例**：`ready.store(true, std::memory_order_release); ready.load(std::memory_order_acquire);`
- **常见误解**：认为把一个标志改成原子类型后，整个函数中的所有共享数据都自然线程安全。

### `volatile` 限定（volatile qualification）

- **定义**：`volatile` 限定用于表示对象可能受程序正常执行流之外的因素影响，并使通过相应 `volatile` 泛左值进行的访问成为实现必须保留的可观察副作用；它不建立 C++ 线程间同步。
- **决定什么**：它约束实现保留相关访问，常用于实现文档规定的设备寄存器等特殊场景。
- **不决定什么**：它不提供原子性、互斥、先后关系或跨线程可见性保证，不能替代 `std::atomic` 和互斥量。
- **最小示例**：`volatile std::uint32_t* device_status = /* 平台提供的地址 */;`
- **常见误解**：把“编译器不能随意消去某类访问”误当成“多个线程读写就是安全的”。
