# 第 10 天术语：复制资源为什么危险

[上一天术语](day09.md) · [返回术语索引](../glossary.md) · [阅读第 10 天讲义](../../days/day10.md)

本文件只保存第 10 天首次出现术语的规范定义。直观模型和完整推理请结合当天讲义阅读。

### 拷贝构造函数（copy constructor）

- **定义**：拷贝构造函数是用同类对象初始化一个新对象的构造函数，其首个参数通常写作 `const T&`，并负责建立新对象的独立有效状态。
- **决定什么**：它决定 `T copy{source}`、按值传递等需要从已有同类对象初始化新对象时，各成员和所拥有资源怎样复制。
- **不决定什么**：拷贝构造函数不处理已经存在对象的赋值，也不保证编译器永远实际执行一次可观察拷贝，因为标准允许特定拷贝消除。
- **最小示例**：

  ```cpp
  Buffer(const Buffer& other)
      : size_{other.size_}, data_{new int[size_]} {}
  ```

- **常见误解**：把 `T b{a};` 说成先默认构造 `b` 再调用赋值运算符。

### 拷贝赋值运算符（copy assignment operator）

- **定义**：拷贝赋值运算符是把一个已有同类对象的状态复制到另一个已经完成初始化的对象中的非静态成员函数，常见签名为 `T& operator=(const T&)`。
- **决定什么**：它决定 `target = source` 时如何替换目标旧状态、处理旧资源并返回赋值结果。
- **不决定什么**：它不负责创建目标对象，也不能假定左右对象一定不同或拥有相同大小的资源。
- **最小示例**：

  ```cpp
  Buffer& operator=(const Buffer& other) {
      if (this == &other) return *this;
      // 复制并替换资源
      return *this;
  }
  ```

- **常见误解**：认为拷贝构造和拷贝赋值只是两种拼写，或忘记赋值前目标对象可能已经拥有必须处理的资源。

### 资源所有权（resource ownership）

- **定义**：资源所有权是对象或程序组件承担在约定时机结束所管理资源的有效使用并执行恰好一次相应释放操作的责任关系。
- **决定什么**：它决定谁负责释放动态存储、文件句柄等资源，以及资源能否被独占、共享或仅观察。
- **不决定什么**：裸指针值本身不自动说明是否拥有资源，同一地址相等也不代表两个对象可以各自释放一次。
- **最小示例**：

  ```cpp
  class Buffer {
      int* data_;  // 若 Buffer 拥有该数组，析构时必须匹配 delete[]
  };
  ```

- **常见误解**：看到类里有指针就断言它一定拥有资源，或认为把指针复制给另一个对象就自动复制了所有权契约。

### 浅拷贝与深拷贝（shallow copy and deep copy）

- **定义**：在本课程资源类语境中，浅拷贝只复制资源句柄或指针值，使多个对象指向同一底层资源；深拷贝则为目标建立独立资源并复制资源内容。
- **决定什么**：选择的拷贝语义决定修改是否相互影响，以及多个对象能否各自安全结束自己的资源所有权。
- **不决定什么**：深拷贝并非所有类型都正确，共享所有权或不可拷贝类型也可能是更符合业务的设计。
- **最小示例**：

  ```cpp
  int* copy{new int[count]};
  std::copy(source, source + count, copy);  // 独立数组
  ```

- **常见误解**：把“复制了一个指针对象”误说成“动态数组内容已经被复制”。

### Rule of Three（三法则）

- **定义**：Rule of Three 是 C++11 之前形成、在现代 C++ 中仍用于理解资源类的设计规则：若类需要自定义析构函数、拷贝构造函数或拷贝赋值运算符中的一个，通常应一起审视并正确设计三者。
- **决定什么**：它提醒资源类同时处理销毁、新对象拷贝和已有对象赋值三条路径，避免只修复其中一条。
- **不决定什么**：它不是要求每个类都手写三者的语言强制规则，也不是 Rule of Five 或 Rule of Zero 的替代品。
- **最小示例**：

  ```cpp
  ~Buffer();
  Buffer(const Buffer&);
  Buffer& operator=(const Buffer&);
  ```

- **常见误解**：认为“三法则”是编译器语法检查，或给所有只含标准库值成员的类机械添加三套函数。
