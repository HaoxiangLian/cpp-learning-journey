# 第 4 天术语：函数如何划分责任

[上一天术语](day03.md) · [返回术语索引](../glossary.md) · [阅读第 4 天讲义](../../days/day04.md)

本文件只保存第 4 天首次出现术语的规范定义。直观模型和完整推理请结合当天讲义阅读。

### 形参与实参（parameter and argument）

- **定义**：形参是在函数声明或定义的参数列表中声明的输入位置及其类型约束；实参是在函数调用表达式中提供、用于初始化对应形参的表达式。
- **决定什么**：形参规定一次调用需要匹配哪些输入，实参决定这次调用实际提供哪些表达式。
- **不决定什么**：名称是否相同不参与匹配；实参也不必是变量，字面量和其他表达式都可以作为实参。
- **最小示例**：

  ```cpp
  int next_count(int current_count) {  // current_count 是形参
      return current_count + 1;
  }

  int result{next_count(3)};           // 3 是实参
  ```

- **常见误解**：把函数定义中的 `current_count` 和调用处的 `3` 都称为参数，因而无法准确描述调用两侧的数据关系。

### 返回值（return value）

- **定义**：返回值是非 `void` 函数的一次调用完成时，按照函数返回类型交给该调用表达式的结果值。
- **决定什么**：返回值让调用表达式可以继续参与初始化、赋值或其他运算。
- **不决定什么**：返回值不保证调用方一定保存结果，也不代表函数可以遗漏某些需要返回的控制路径。
- **最小示例**：

  ```cpp
  int next_count(int current_count) {
      return current_count + 1;  // 返回值为计算结果
  }
  ```

- **常见误解**：认为 `return` 只负责离开函数，与函数声明的返回类型没有关系。

### 值传递（pass by value）

- **定义**：值传递是用实参的值初始化一个非引用形参对象，使函数体操作该独立形参对象的传参方式。
- **决定什么**：在本阶段的基本类型示例中，修改形参不会修改调用方提供实参的原对象。
- **不决定什么**：值传递不保证机器代码一定执行一条物理复制指令；类类型还可能涉及拷贝、移动或省略，后续课程再展开。
- **最小示例**：

  ```cpp
  int add_one(int count) {
      ++count;
      return count;
  }
  ```

- **常见误解**：认为形参名称与调用方变量名称相同，就会让两者成为同一个对象。

### 函数重载（function overloading）

- **定义**：函数重载是在同一作用域中让多个函数使用同一名称和可区分的参数列表，并在调用处通过重载决议选择唯一最佳可行函数的机制。
- **决定什么**：决定同一操作名称如何根据实参数量、类型和允许的转换选择具体函数。
- **不决定什么**：返回类型不同不能单独构成重载；若不存在唯一最佳可行函数，调用就是编译错误。
- **最小示例**：

  ```cpp
  void report(int value);
  void report(double value);
  ```

- **常见误解**：认为只要函数体不同或返回类型不同，就能形成合法重载。

### 默认实参（default argument）

- **定义**：默认实参是在函数声明中为形参指定的表达式，当调用省略对应实参时，该表达式用于补足这次调用。
- **决定什么**：决定调用方在允许的位置省略实参时使用什么表达式。
- **不决定什么**：默认实参不会创建新的函数或新的重载，也不是函数返回失败时使用的备用值。
- **最小示例**：

  ```cpp
  int score(int tasks, int points_per_task = 10);
  ```

- **常见误解**：认为带默认实参的一个函数等同于多个重载函数。

### 递归（recursion）

- **定义**：递归是函数在执行过程中直接或间接再次调用自身的调用结构。
- **决定什么**：递归关系决定问题怎样缩小到后续调用，终止条件决定何时不再递归。
- **不决定什么**：递归不保证一定终止，也不保证编译器执行尾调用优化；C++ 标准不要求用某种特定“调用栈”布局实现它。
- **最小示例**：

  ```cpp
  int sum_to(int n) {
      if (n <= 0) {
          return 0;
      }
      return n + sum_to(n - 1);
  }
  ```

- **常见误解**：只写一个停止分支就认为递归一定能到达它，而没有检查每次调用是否真正向停止条件推进。
