# 第 16 天术语：顺序容器、容量与迭代器失效

本文件只保存第 16 天首次引入术语的规范定义。定义在讲义首次使用处原句重复；请先结合当时的代码和状态变化理解，再用本页复述。

### 顺序容器与 `std::vector`（sequence container and vector）

- **定义**：顺序容器是元素次序由插入顺序及插入位置决定的一类标准容器；`std::vector<T>`（除 `bool` 特化）是其中自动管理可变长度连续元素序列、支持常量时间随机访问和末尾摊销常量时间插入的类模板。
- **决定什么**：`std::vector<int>` 保存一组有顺序的 `int` 元素，自己记录元素数量并管理相应存储；下标和迭代器可访问当前合法范围中的元素。
- **不决定什么**：容器不会替调用者证明下标有效，也不保证元素地址在修改大小后始终不变；`vector<bool>` 是标准库的特殊特化，不提供普通 `vector<T>` 的全部连续元素引用性质。
- **最小示例**：

  ```cpp
  std::vector<int> readings{4, 9, 2};
  readings.push_back(7);
  ```

- **常见误解**：把 `vector` 当成“永远不会移动的数组”，或以为 `operator[]` 会自动检查越界。

### 大小、容量、`reserve`、`resize` 与重新分配（size, capacity, reserve, resize and reallocation）

- **定义**：`std::vector` 的 `size` 是当前元素数量，`capacity` 是无需重新分配即可容纳的元素数量；`reserve(n)` 只提出至少容纳 `n` 个元素的容量要求而不改变 `size`，`resize(n)` 则把元素数量改为 `n`，重新分配是容器取得新存储并把现有元素转移到其中的过程。
- **决定什么**：`size()` 决定合法元素范围，`capacity()` 决定继续插入多少元素以前可保证无需重新分配；增大 `resize` 会创建元素，减小它会移除末尾元素。
- **不决定什么**：标准不规定具体容量增长倍率；`reserve` 不创建可用元素，`shrink_to_fit` 也只是非强制的缩容请求。
- **最小示例**：

  ```cpp
  std::vector<int> values{4, 9, 2};
  values.reserve(values.capacity() + 5);
  values.resize(5, 0);
  ```

- **常见误解**：执行 `reserve(100)` 后直接读写 `values[99]`，或把 `resize` 当成只改变预留空间。

### 复杂度与摊销复杂度（complexity and amortized complexity）

- **定义**：复杂度描述操作所需工作量如何随元素数量 `n` 增长；摊销复杂度把一串操作中少数高成本步骤分摊到整串操作，给出每次操作的长期上界，而不保证每一次都同样便宜。
- **决定什么**：常量复杂度表示工作量不随 `n` 成比例增长，线性复杂度表示工作量最多按 `n` 的量级增长；摊销常量时间允许偶发的线性重新分配。
- **不决定什么**：复杂度不等同于某台机器上的具体纳秒数，也不单独决定真实程序性能；元素大小、内存访问和实际操作比例仍会影响结果。
- **最小示例**：

  ```cpp
  values.push_back(7);  // vector 末尾插入：摊销常量时间
  ```

- **常见误解**：把“摊销常量”说成每一次 `push_back` 都绝不移动旧元素，或仅凭大 O 符号断言 `list` 一定比 `vector` 快。

### `std::deque` 与 `std::list`（deque and list）

- **定义**：`std::deque` 是支持随机访问、并保证在首尾常量时间插入和删除的顺序容器；`std::list` 是只提供双向迭代、不提供随机访问、但在已知位置可常量时间插入或删除单个元素的顺序容器。
- **决定什么**：需要频繁操作首尾且仍要按下标访问时可考虑 `deque`；已经持有插入/删除位置、且更重视其他元素位置稳定性时可考虑 `list`。
- **不决定什么**：`list` 的常量时间插入不包含从头寻找第 `n` 个位置的时间；`deque` 也不保证全部元素连续存储，二者都不是在所有场景下优于 `vector`。
- **最小示例**：

  ```cpp
  std::deque<int> queue{20};
  queue.push_front(10);

  std::list<int> route{10, 30};
  auto position = route.begin();
  ++position;
  route.insert(position, 20);
  ```

- **常见误解**：因为 `list` 在已知位置插入是常量时间，就忽略寻找该位置的线性遍历；或对 `deque` 元素做连续内存假设。

### 迭代器失效（iterator invalidation）

- **定义**：迭代器失效是容器修改使先前取得的迭代器不再可用于原来的遍历或访问；同一修改是否也使指针或引用失效，取决于具体容器、操作位置以及是否发生重新分配。
- **决定什么**：失效规则决定修改容器后哪些旧位置必须丢弃并重新取得；使用已经失效的迭代器访问元素通常产生未定义行为。
- **不决定什么**：容器内容仍然存在不代表旧迭代器仍有效；也不能把 `list` 的稳定规则推广给 `vector` 或 `deque`。
- **最小示例**：

  ```cpp
  auto old = values.begin();
  values.reserve(values.capacity() + 1);  // 必然重新分配
  // old 已失效，必须重新调用 begin()
  ```

- **常见误解**：修改后看到元素值没变，就继续解引用旧迭代器；或认为“迭代器失效”意味着容器对象本身已经销毁。
