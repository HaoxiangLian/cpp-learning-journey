### 预处理与翻译单元（preprocessing and translation unit）

- **定义**：预处理是正式编译前处理 `#include`、条件编译和宏等预处理指令并形成待翻译内容的阶段；一个源文件连同预处理后纳入的内容构成一个翻译单元，通常与其他翻译单元分别编译。
- **决定什么**：它决定当前源文件实际向编译器提供哪些声明和定义，并划出分别进行语法与类型检查的输入边界。
- **不决定什么**：`#include` 不是运行时读取文件；翻译单元也不等同于最终可执行程序，跨单元引用仍要经过链接。
- **最小示例**：`#include "reading.hpp"  // 将头文件内容纳入当前翻译单元`
- **常见误解**：认为编译器直接把整个项目一次性当成一个大文件处理，或认为头文件会在程序运行时动态加载。

### 头文件保护与单一定义规则（header guard and One Definition Rule）

- **定义**：头文件保护用条件预处理使同一头文件在一个翻译单元中只生效一次；单一定义规则规定实体在程序中允许出现多少个定义以及多处定义必须满足什么条件。
- **决定什么**：保护宏避免同一翻译单元重复纳入类等定义；单一定义规则约束跨翻译单元的普通函数、变量、类、模板和 `inline` 实体定义。
- **不决定什么**：保护宏只处理当前翻译单元的重复包含，不能让任意普通函数定义安全地散布到多个翻译单元。
- **最小示例**：`#ifndef PROJECT_READING_HPP`、`#define PROJECT_READING_HPP`、`#endif`
- **常见误解**：以为“加了 include guard”就同时解决所有链接阶段的多重定义问题。

### CMake 目标与构建依赖图（CMake target and build dependency graph）

- **定义**：CMake 目标是构建系统中的命名产物及其源文件、依赖和使用要求；目标之间的依赖关系共同形成构建依赖图，CMake 据此生成具体构建工具所需规则。
- **决定什么**：它决定哪些源文件组成可执行文件或库、目标链接哪些库，以及哪些包含目录、编译特性和选项传播到哪里。
- **不决定什么**：CMake 不替编译器检查 C++ 语义，也不保证列出的源文件内容、业务逻辑或运行时行为正确。
- **最小示例**：`add_executable(day22_example main.cpp reading.cpp)`
- **常见误解**：把 `CMakeLists.txt` 当成按行直接编译源码的脚本，或把全局选项无差别施加给所有第三方目标。

### 调试器、断点与单步执行（debugger, breakpoint and stepping）

- **定义**：调试器是控制并观察被调试程序执行的工具；断点让程序在指定位置暂停，单步执行让程序按源代码行或指令逐步推进，以便检查变量、调用关系和控制流。
- **决定什么**：它允许在一次具体执行中停在错误附近，观察当时的对象值、当前调用位置和后续路径。
- **不决定什么**：调试器不会自动证明根因，也不能保证被调试构建与优化后的发布构建具有完全相同的时间、布局或并发表现。
- **最小示例**：`gdb ./day22_example` 后执行 `break is_valid`、`run`、`next`、`print reading.value`。
- **常见误解**：只要在崩溃行停住就已找到根因，忽略错误状态可能在更早的位置形成。

### Sanitizer 动态检测（Sanitizer dynamic checking）

- **定义**：Sanitizer 动态检测是编译器为程序加入运行时检查并在执行到可检测错误时报告诊断的工具方式；AddressSanitizer 重点检测部分内存错误，UndefinedBehaviorSanitizer 重点检测部分未定义行为。
- **决定什么**：它能为实际运行覆盖到的受支持错误提供位置、调用信息和错误类别，帮助缩小排查范围。
- **不决定什么**：一次无报告运行不能证明程序没有错误；Sanitizer 不能覆盖未执行路径、所有未定义行为、数据竞争或全部业务逻辑错误。
- **最小示例**：`c++ -fsanitize=address,undefined -fno-omit-frame-pointer main.cpp`
- **常见误解**：把 Sanitizer 当成静态证明工具，或认为 ASan 能自动检测所有并发数据竞争。
