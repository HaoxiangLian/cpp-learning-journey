# 第 19 天术语：RAII、异常传播与异常安全

### RAII（resource acquisition is initialization）

- **定义**：RAII 是把资源的有效使用期绑定到对象生命周期的 C++ 设计方法：对象初始化时建立资源管理责任，对象销毁时由析构过程自动结束该资源。
- **决定什么**：只要管理对象正常进入销毁过程，普通返回和异常传播都能沿同一条析构路径清理资源。
- **不决定什么**：RAII 不要求资源必须是动态内存，也不保证资源取得、业务操作或清理动作本身永远不会失败。
- **最小示例**：`std::lock_guard<std::mutex> guard{mutex};`
- **常见误解**：把 RAII 解释成“只要写了构造函数和析构函数就安全”，却没有明确一个对象到底管理什么以及是否会被重复管理。

### 异常传播与栈展开（exception propagation and stack unwinding）

- **定义**：异常传播是 `throw` 产生的异常沿调用关系寻找匹配处理器的过程；栈展开是在这段离开路径上按规则销毁已经成功构造的自动对象的过程。
- **决定什么**：异常会跳过未执行的后续语句，并在进入匹配 `catch` 前结束沿途作用域中的局部对象。
- **不决定什么**：抛异常不表示进程必然终止；也不表示尚未完成构造的整个对象会调用自身析构函数。
- **最小示例**：`try { run(); } catch (const std::exception& error) { /* 处理 */ }`
- **常见误解**：认为异常会直接跳到 `catch`，沿途局部对象都来不及析构。

### 异常安全保证（exception safety guarantee）

- **定义**：异常安全保证是操作发生异常时对程序状态和资源作出的承诺：基本保证要求状态仍有效且无资源泄漏，强保证进一步要求对外状态保持调用前的样子，不抛保证则承诺异常不会离开该操作。
- **决定什么**：它规定失败之后调用者还能依赖哪些状态，而不是规定操作采用哪一种具体实现算法。
- **不决定什么**：强保证不表示操作不会失败，基本保证也不表示值完全不变；一个组合操作的保证取决于其中各步骤及提交顺序。
- **最小示例**：`validate(candidate); value = candidate;  // 先检查，后提交`
- **常见误解**：把“捕获了异常”等同于异常安全，或把基本保证误说成失败后所有值都恢复原样。

### `noexcept` 说明（noexcept specification）

- **定义**：`noexcept` 说明是函数类型的一部分，用来承诺异常不会越过该函数调用边界；若异常仍从不抛函数逃出，运行时调用 `std::terminate`。
- **决定什么**：它让调用者和标准库知道该调用是否承诺不抛，并可影响某些泛型代码选择移动还是复制路径。
- **不决定什么**：`noexcept` 不会自动捕获函数体内部的异常，也不把所有潜在 `throw` 自动变成编译错误。
- **最小示例**：`void close_device() noexcept;`
- **常见误解**：认为加上 `noexcept` 就会让可能失败的代码自动安全，或认为它只是一条优化提示。
