# 第 9 天术语：对象怎样出生和结束

[上一天术语](day08.md) · [返回术语索引](../glossary.md) · [阅读第 9 天讲义](../../days/day09.md)

本文件只保存第 9 天首次出现术语的规范定义。直观模型和完整推理请结合当天讲义阅读。

### 构造函数（constructor）

- **定义**：构造函数是类的特殊成员函数，在类类型对象初始化时被选择调用，以建立该对象及其成员的初始状态。
- **决定什么**：它决定哪些初始化形式可创建对象，以及在构造函数体开始前应怎样初始化基类和非静态数据成员。
- **不决定什么**：构造函数不是普通“返回一个对象”的函数，没有返回类型，也不能改变成员依照语言规则确定的初始化顺序。
- **最小示例**：

  ```cpp
  class Task {
  public:
      explicit Task(int id) : id_{id} {}
  private:
      int id_;
  };
  ```

- **常见误解**：认为成员进入构造函数体时仍完全不存在，因此在函数体内赋值与成员初始化列表没有区别。

### 成员初始化列表（member initializer list）

- **定义**：成员初始化列表是构造函数声明体之前、冒号之后的一组初始化器，用来直接指定基类和非静态数据成员的初始化参数。
- **决定什么**：它为对应子对象提供初始化器，并能直接初始化没有默认构造后再赋值路径的 `const` 或引用成员。
- **不决定什么**：列表的书写先后不决定实际初始化次序；未列出的成员仍按默认成员初始化器或其他初始化规则处理。
- **最小示例**：

  ```cpp
  Task(int id, bool active) : id_{id}, active_{active} {}
  ```

- **常见误解**：把冒号后的列表叫作“赋值列表”，或通过调整列表顺序试图改变成员真实初始化顺序。

### 初始化与析构顺序（initialization and destruction order）

- **定义**：初始化与析构顺序是类子对象按语言固定次序建立并按相反次序销毁的规则；非静态数据成员按它们在类定义中的声明顺序初始化，并按逆序析构。
- **决定什么**：它决定成员之间依赖何时有效，也决定已构造子对象在对象结束时的逆序清理次序。
- **不决定什么**：构造函数成员初始化列表的排列不能覆盖声明顺序，常见 ABI 的字段偏移也不能替代该语义规则。
- **最小示例**：

  ```cpp
  class Task {
      Sensor sensor_;   // 先初始化，后析构
      Planner planner_; // 后初始化，先析构
  };
  ```

- **常见误解**：认为“初始化列表里先写谁就先构造谁”，从而让前面的成员读取尚未初始化的后声明成员。

### 析构函数（destructor）

- **定义**：析构函数是类的特殊成员函数，在类对象销毁过程中被调用，用于执行该类层级的结束操作，并由语言继续销毁成员和基类子对象。
- **决定什么**：它提供对象生命周期结束时执行类自身清理逻辑的位置，并参与成员和基类的逆序销毁过程。
- **不决定什么**：析构函数不等于释放对象本身所占的所有存储，手动调用析构函数也不等于普通代码中可以再次自动析构同一对象。
- **最小示例**：

  ```cpp
  ~Task() {
      std::cout << "task closed\n";
  }
  ```

- **常见误解**：认为离开任何花括号都会调用所有对象的析构函数，忽略对象的实际存储期与生命周期。

### explicit 构造函数（explicit constructor）

- **定义**：`explicit` 构造函数是不能作为普通隐式用户定义转换被自动采用、但仍可通过直接初始化或显式转换调用的构造函数。
- **决定什么**：它阻止调用方在没有明确写出目标类型时，意外用构造参数自动形成该类对象。
- **不决定什么**：`explicit` 不禁止 `Type{argument}`、`Type(argument)` 等直接初始化，也不表示构造函数更高效或更安全地检查参数值。
- **最小示例**：

  ```cpp
  explicit RetryLimit(int count);
  RetryLimit limit{3};  // 直接初始化，合法
  ```

- **常见误解**：认为 `explicit` 会禁止一切构造调用，或认为所有多参数构造函数都与隐式转换绝对无关。
