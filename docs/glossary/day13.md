# 第 13 天术语：运行时多态与对象模型

[上一天术语](day12.md) · [返回术语索引](../glossary.md) · [阅读第 13 天讲义](../../days/day13.md)

本文件只保存第 13 天首次正式定义术语的规范表述。代码现象、依赖顺序和完整推理请结合当天讲义阅读。

### 虚函数（virtual function）

- **定义**：虚函数是在类中首次用 `virtual` 声明、并允许通过基类接口调用时根据完整对象选择相应派生实现的非静态成员函数；派生类中符合规则的对应版本也继续为虚函数。
- **决定什么**：它使基类接口可以在完整派生对象仍存在时选择相应派生行为，是运行时多态的函数入口。
- **不决定什么**：引用或指针本身不会把普通函数变成虚函数；`virtual` 也不规定编译器必须使用某种虚函数表布局。
- **最小示例**：

  ```cpp
  class Sensor {
  public:
      virtual int read() const { return 0; }
  };
  ```

- **常见误解**：认为只要参数是基类引用，所有同名成员都会自动调用派生版本。

### 运行时多态与动态绑定（runtime polymorphism and dynamic binding）

- **定义**：运行时多态是在通过基类接口调用虚函数时，根据该接口实际引用或指向的完整对象选择相应函数实现的行为；这种调用选择称为动态绑定。
- **决定什么**：它决定一次未显式限定的虚调用最终执行基类版本还是某个派生覆盖版本。
- **不决定什么**：它不会恢复已经因按值复制而切掉的派生部分，也不要求程序运行时一定进行可观察的虚表间接跳转。
- **最小示例**：

  ```cpp
  Lidar lidar;
  const Sensor& sensor{lidar};
  sensor.read();  // 若 read 为虚函数，按完整 Lidar 选择实现
  ```

- **常见误解**：把“基类引用没有切片”和“任何函数都会动态选择”当成同一件事。

### 覆盖与 `override`（overriding and override specifier）

- **定义**：函数覆盖是派生类成员函数满足基类虚函数的覆盖规则并成为相应对象候选最终实现的关系；`override` 是写在派生函数声明末尾的 C++11 说明符，若该函数没有真正覆盖基类虚函数，程序即为非良构。
- **决定什么**：覆盖建立基类虚入口与派生实现之间的关系；`override` 让编译器检查这层关系是否真的成立。
- **不决定什么**：`override` 不是开启虚调用的关键字，也不会自动修正参数、`const`、引用限定或返回类型错误。
- **最小示例**：

  ```cpp
  class Lidar : public Sensor {
  public:
      int read() const override { return 64; }
  };
  ```

- **常见误解**：删除报错的 `override` 就当作修复，实际留下一个没有覆盖基类入口的同名函数。

### 纯虚函数与抽象类（pure virtual function and abstract class）

- **定义**：纯虚函数是用 `= 0` 纯说明符声明的虚函数；抽象类是至少有一个最终覆盖函数仍为纯虚、因而不能直接创建该类对象的类。
- **决定什么**：纯虚函数规定具体派生类需要提供的行为；抽象性决定该类型能否直接按值创建对象。
- **不决定什么**：抽象类仍可有构造函数、数据成员和已实现函数，也可以作为指针或引用的目标类型。
- **最小示例**：

  ```cpp
  class Sensor {
  public:
      virtual double read() const = 0;
  };
  ```

- **常见误解**：认为抽象类中不能有任何实现，或认为 `= 0` 是一个可以执行的空函数体。

### 对齐与填充（alignment and padding）

- **定义**：对齐要求是对象类型对其可放置地址施加的限制，可用 `alignof(T)` 查询完整对象情形的要求；填充是实现为满足对齐和数组连续放置等要求而在类对象表示中保留、但不对应普通成员值的字节。
- **决定什么**：对齐会限制对象可放置的位置，填充会影响类对象的 `sizeof` 以及数组元素间距。
- **不决定什么**：成员列表不能唯一决定跨平台对象大小；对齐和填充也不证明对象内必有某个固定位置的 vptr。
- **最小示例**：

  ```cpp
  struct Record {
      char valid;
      int value;
  };

  static_assert(sizeof(Record) >= sizeof(char) + sizeof(int));
  ```

- **常见误解**：把一台机器上的 `sizeof`、成员偏移或常见 vtable 示意图当成 C++ 标准规定的统一布局。
