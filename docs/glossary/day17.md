# 第 17 天术语：关联容器、比较器、哈希与重新散列

### 关联容器、键与 `std::map`/`std::set`（associative container, key, map and set）

- **定义**：关联容器是根据键而不是插入位置组织并检索元素的一类标准容器；`std::set<Key>` 保存唯一的键，`std::map<Key, T>` 保存唯一键到映射值的对应关系，二者都按比较器定义的键序迭代。
- **决定什么**：`set` 适合回答“某个键是否存在”，`map` 适合根据键取得或修改对应值；默认比较器通常让整数或字符串键按升序迭代。
- **不决定什么**：`map` 的第二个模板实参不是第二个键；`map` 和 `set` 也不是按插入先后保存元素，重复插入等价键不会让唯一键容器同时保存两份。
- **最小示例**：

  ```cpp
  std::map<std::string, int> limits{{"force", 8}};
  std::set<int> active_ids{7, 2, 7};
  ```

- **常见误解**：把 `map` 当成两个并排的数组，或认为 `set` 会保留所有重复值及其插入顺序。

### 比较器与严格弱序（comparison object and strict weak ordering）

- **定义**：比较器是有序关联容器用来回答“一个键是否排在另一个键之前”的可调用对象；它必须给键建立严格弱序，而两个方向比较结果都为 `false` 的键会被容器视为等价键。
- **决定什么**：比较器同时决定迭代顺序和唯一键判断；对默认 `std::less<int>`，较小整数排在前面，数值相同的键等价。
- **不决定什么**：比较器不需要回答两个键是否完全相等；容器的等价关系也不一定与键类型的 `operator==` 结果相同。
- **最小示例**：

  ```cpp
  struct TensGroupLess {
      bool operator()(int lhs, int rhs) const {
          return lhs / 10 < rhs / 10;
      }
  };
  ```

- **常见误解**：把 `lhs <= rhs` 当作合法的“先于”关系；它会让 `comp(x, x)` 为真，不满足严格弱序的基本要求。

### 无序关联容器（unordered associative container）

- **定义**：无序关联容器是使用哈希函数和键相等判定按键组织元素、但不保证整体迭代顺序的一类标准容器；`std::unordered_set<Key>` 保存唯一键，`std::unordered_map<Key, T>` 保存唯一键到映射值的对应关系。
- **决定什么**：在哈希分布和负载正常时，按键插入、查找和删除通常具有平均常量复杂度；键值对应关系不依赖当前遍历先后。
- **不决定什么**：名称中的“无序”不表示元素随机或无法查找，也不提供稳定的插入顺序、升序或跨运行相同的遍历顺序。
- **最小示例**：

  ```cpp
  std::unordered_map<int, std::string> labels{{7, "force"}};
  auto found = labels.find(7);
  ```

- **常见误解**：因为一次运行恰好以某个顺序输出，就把该顺序写入程序正确性或测试断言。

### 哈希函数、桶与哈希冲突（hash function, bucket and hash collision）

- **定义**：哈希函数把键转换为 `std::size_t` 哈希值，桶是无序容器组织候选元素的分组；不同键得到同一哈希值并进入同一桶称为哈希冲突，冲突不表示两个键相等或元素被覆盖。
- **决定什么**：键相等判定认为等价的两个键必须得到相同哈希值；良好的哈希分布能减少一个桶内需要继续比较的候选元素。
- **不决定什么**：不同键不必得到不同哈希值；标准也不固定桶内使用链表、开放寻址或某种具体内存布局。
- **最小示例**：

  ```cpp
  struct LastDigitHash {
      std::size_t operator()(int key) const {
          return static_cast<std::size_t>(key % 10);
      }
  };
  ```

- **常见误解**：要求哈希函数绝不冲突，或把哈希值相同直接当作键相等而跳过相等比较。

### 负载因子、重新散列与无序容器失效（load factor, rehash and unordered-container invalidation）

- **定义**：负载因子是 `size()/bucket_count()` 表示的平均每桶元素数；重新散列（rehash）是无序容器改变桶数量并重新安排元素所属桶的过程，它会使所有旧迭代器失效，但不会使指向现存元素的指针和引用失效。
- **决定什么**：插入可能因超过最大负载因子而触发重新散列；`reserve(n)` 为至少容纳 `n` 个元素准备相应桶数，显式 `rehash(n)` 则提出最低桶数要求。
- **不决定什么**：`reserve(n)` 不创建 `n` 个元素，重新散列也不保证迭代顺序保持不变；保留下来的指针或引用在其元素随后被删除时仍会失效。
- **最小示例**：

  ```cpp
  auto old = labels.find(7);
  const std::string* kept = &old->second;
  labels.rehash(labels.bucket_count() + 1);
  // old 已失效，kept 仍指向现存元素
  ```

- **常见误解**：把 Day 16 的 `vector` 重新分配规则直接套给无序容器，误以为重新散列也会使元素引用和指针全部失效。
