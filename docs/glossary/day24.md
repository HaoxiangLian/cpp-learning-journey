# 第 24 天术语：综合验收、最小闭环项目与间隔复习

[返回第 24 天讲义](../../days/day24.md) · [返回术语索引](../glossary.md)

本文件只保存第 24 天首次引入的课程学习工具；它们不是 C++ 标准术语。定义在讲义首次使用处原句重复，请先结合代码、状态表和验收任务理解，再用本页复述。

### 综合验收（integrated assessment）

- **定义**：综合验收是用同一组限时任务同时检查代码能否构建运行、对象状态能否预测、错误能否分类以及结论能否说明条件与边界的验证过程。
- **决定什么**：它让“学完”转化为多项可观察、可复查且能相互印证的能力证据。
- **不决定什么**：一次通过不能证明所有未覆盖路径都正确，也不能替代之后的复习与真实项目反馈。
- **最小示例**：`构建运行 → 对象表 → 错误阶段 → 30 秒条件化回答`。
- **常见误解**：只用选择题分数或一次成功运行代表全部掌握，忽略推理过程和未覆盖边界。

### 最小闭环项目（minimum closed-loop project）

- **定义**：最小闭环项目是能独立完成输入建模、状态约束、核心处理、结果输出和自动验证的一小组可构建代码。
- **决定什么**：它要求每项需求都有可观察结果，并把对象责任、错误处理和验证方式连成一条完整路径。
- **不决定什么**：最小不等于草率，也不表示项目已经具备生产环境所需的性能、并发、部署和运维能力。
- **最小示例**：`任务输入 → TaskQueue 管理 → run_all 处理 → 结果输出 → 构建与动态检查`。
- **常见误解**：堆出很多类和设计模式就算闭环，或者只有一个能运行的 `main` 就不需要说明责任和失败边界。

### 间隔复习（spaced review）

- **定义**：间隔复习是把同一知识在逐渐拉开的时间点主动提取并依据错因调整下一次练习的学习安排。
- **决定什么**：它让复习优先处理真实薄弱项，并通过多次闭卷输出检查知识能否保持和迁移。
- **不决定什么**：固定的四个日期不能保证永久掌握，也不要求每个人或每个知识点使用完全相同的间隔。
- **最小示例**：`+2 天纠错 → +7 天重写 → +14 天改项目 → +30 天重新验收`。
- **常见误解**：把按时重读等同于主动复习，或只记录分数而不记录遗漏条件、对象混淆和错误阶段。
