# 第 23 天术语：代码辨析与条件化回答

[返回第 23 天讲义](../../days/day23.md) · [返回术语索引](../glossary.md)

本文件只保存第 23 天首次引入的课程推理工具；它们不是 C++ 标准术语。定义在讲义首次使用处原句重复，请先结合代码和状态表理解，再用本页复述。

### 代码辨析证据链（code-reasoning evidence chain）

- **定义**：代码辨析证据链是先列出对象、状态变化、管理责任和最后合法使用点，再依据已学语言规则逐步推出结论的检查方法。
- **决定什么**：它决定回答是否能从具体代码事实走到可复核结论，并暴露缺少的条件。
- **不决定什么**：它不是 C++ 语法，也不能替代某个类型、容器或同步操作本身的规则。
- **最小示例**：`源 unique_ptr 负责 → 移动后为空；容器元素接手 → 清空容器时结束对象`。
- **常见误解**：只罗列术语或关键字，却没有说明哪个对象改变、由谁负责以及何时不能再用。

### 条件—结论矩阵（condition-conclusion matrix）

- **定义**：条件—结论矩阵是把一个判断所需的触发条件、在条件成立时可保证的结论以及仍未被保证的边界并排列出的分析表。
- **决定什么**：它帮助区分 vector 失效、动态绑定、同步和复杂度等各自依赖的不同条件。
- **不决定什么**：它不让不同容器或不同并发协议共享同一套结论，也不提供未经测量的性能数字。
- **最小示例**：`若 vector 插入触发重新分配 → 旧元素迭代器失效；仍不能推出被 unique_ptr 管理的对象同时结束`。
- **常见误解**：把某个具体操作下的结论扩大为“所有修改”“所有容器”或“所有实现”都一样。

### 条件化回答（qualified answer）

- **定义**：条件化回答是先给明确结论，再说明结论成立的条件、可核对的规则依据和不能扩大到的边界的答题结构。
- **决定什么**：它让 30 秒回答既直接又能承接条件变化的连续追问。
- **不决定什么**：表达结构不能把错误代码变正确，也不能用含糊的“可能”代替精确条件。
- **最小示例**：`结论 → 条件 → 依据 → 边界`。
- **常见误解**：为了避免绝对化而拒绝下结论，或只补一句“看情况”却不说明看哪些情况。
