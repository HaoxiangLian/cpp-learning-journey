# 第 11 天术语：转移资源而不是复制

[上一天术语](day10.md) · [返回术语索引](../glossary.md) · [阅读第 11 天讲义](../../days/day11.md)

本文件只保存第 11 天首次出现术语的规范定义。直观模型和完整推理请结合当天讲义阅读。

### 右值引用（rvalue reference）

- **定义**：右值引用是以 `T&&` 表示、能够绑定到相应右值并让重载选择区分可被转移来源的引用类型。
- **决定什么**：它让函数签名可以区分通常仍要保留的来源与可用于移动路径的来源，并为移动构造、移动赋值提供参数形式。
- **不决定什么**：出现 `T&&` 不会自动搬运成员，也不保证所绑定对象随后为空；函数体和类型契约仍决定实际操作。
- **最小示例**：

  ```cpp
  Buffer(Buffer&& source);  // source 是有名字的形参
  ```

- **常见误解**：把两个 `&` 理解成“两个地址”，或认为右值引用本身已经释放、复制或清空了源对象。

### 移动构造函数（move constructor）

- **定义**：移动构造函数是以同类右值引用初始化新对象的构造函数，通常通过接管源对象可转移资源并把源对象留在满足其契约的有效状态来建立目标。
- **决定什么**：它决定从可移动来源建立新对象时，哪些成员被接管、源对象留下什么可用状态。
- **不决定什么**：它不处理已经存在目标对象的旧资源，也不保证移动必然比拷贝快或必然发生。
- **最小示例**：

  ```cpp
  Buffer(Buffer&& source)
      : data_{source.data_} {
      source.data_ = nullptr;
  }
  ```

- **常见误解**：只复制拥有型指针却不复位源对象，导致两个对象都认为自己负责释放同一资源。

### `std::move`

- **定义**：`std::move` 是把实参显式转换为相应右值引用表达式的标准库函数；它本身不搬运资源，后续被选择的操作决定是否以及怎样移动。
- **决定什么**：它表达调用方愿意把实参交给可接受右值引用的重载处理，并影响重载选择。
- **不决定什么**：它不执行成员复制、不保证命中移动操作，也不规定调用后对象的具体值。
- **最小示例**：

  ```cpp
  Buffer target{std::move(source)};
  ```

- **常见误解**：把 `std::move` 当作会立即清空对象的命令，忽略目标类型可能只有拷贝操作或被选操作可能采用别的策略。

### 移动赋值运算符（move assignment operator）

- **定义**：移动赋值运算符是把可移动来源的状态转移到一个已经完成初始化的同类目标对象中的非静态成员函数，常见签名为 `T& operator=(T&&)`。
- **决定什么**：它决定目标旧状态如何结束、源资源如何接管、源对象和返回值处于什么有效状态。
- **不决定什么**：它不负责创建目标对象，也不能忽略目标原来可能已经拥有资源或目标与源可能是同一对象。
- **最小示例**：

  ```cpp
  Buffer& operator=(Buffer&& source) {
      // 处理旧资源，再接管 source
      return *this;
  }
  ```

- **常见误解**：直接覆盖目标拥有型指针，造成目标旧资源泄漏，或把移动赋值与移动构造混为一谈。

### 移后状态（moved-from state）

- **定义**：移后状态是对象作为移动操作的非 `const` 来源后仍处于生命周期内、满足该类型所承诺约束但具体可观察值由其契约决定的状态。
- **决定什么**：类型契约决定移动后允许执行哪些操作、能否读取特定值以及重新赋值后怎样继续使用。
- **不决定什么**：它不统一等于“空”“零”或“不可使用”；标准库类型在未另行说明时通常保证有效但值未指定。
- **最小示例**：

  ```cpp
  Buffer target{std::move(source)};
  source = Buffer{2};  // 若赋值满足契约，可重新建立状态
  ```

- **常见误解**：把被移动对象当作已析构对象，或无条件断言所有类型移动后都为空。

### Rule of Five（五法则）

- **定义**：Rule of Five 是现代 C++ 的资源类设计提醒：若类需要自定义析构、拷贝构造、拷贝赋值、移动构造或移动赋值中的一个，通常应共同审视这五条特殊成员路径。
- **决定什么**：它提醒设计者为销毁、复制和转移明确一致的资源所有权语义。
- **不决定什么**：它不是要求每个类都手写五个函数的标准语法，也不保证机械补齐五个函数就得到正确设计。
- **最小示例**：

  ```cpp
  ~Buffer();
  Buffer(const Buffer&);
  Buffer& operator=(const Buffer&);
  Buffer(Buffer&&);
  Buffer& operator=(Buffer&&);
  ```

- **常见误解**：认为编译器会因为“五法则”自动报错，或给只含标准库值成员的普通类机械添加五个函数。

### Rule of Zero（零法则）

- **定义**：Rule of Zero 是让专门的资源管理类型承担释放、复制和移动，使业务类无需自行声明析构、拷贝或移动特殊成员函数的设计原则。
- **决定什么**：成员类型的语义会组合成业务类的默认销毁、复制和移动行为，减少手写所有权代码。
- **不决定什么**：它不表示对象没有资源或析构行为，也不表示所有成员都必须可复制。
- **最小示例**：

  ```cpp
  class Samples {
      std::vector<int> values_;  // vector 自己管理动态存储
  };
  ```

- **常见误解**：把 Rule of Zero 理解为“类中不能有资源”，而不是“业务类不亲自实现资源管理细节”。
